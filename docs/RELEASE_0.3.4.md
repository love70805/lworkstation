# 0.3.4 采集恢复与发布验收

2026-09-30 10:23（北京时间），[v0.3.4](https://github.com/love70805/lworkstation/releases/tag/v0.3.4)已公开为稳定Latest；[PR #129](https://github.com/love70805/lworkstation/pull/129)已通过保护合并。ERP Assistant 8.0.25统一交付。本机不安装，不改真实业务数据库或已定稿报告。基线main `e52c9a457f0ff0adeabb1a8fa1542f0593ca157f`，复用d308，分支 `codex/release-0-3-4`。

## 根因与修复

用户反馈长久停在“读取第一页”；内嵌运行时8.0.24已由决策端只读确认，现场没有可用于确定唯一根因的网络堆栈。源码确认两条可复现缺陷：原成本计算必须等可选目录及逐仓库采购补取完成才显示/回传，已有完整证据仍重复读取；“读取第1页”在补取阶段再次出现。首次请求20秒×3重试缺少阶段反馈，JSON读取及不响应AbortSignal的fetch也缺少独立硬期限，页大小回退可重复整轮重试。

成本现在在原证据与映射完成后先缓存、展示及回传，商品资料随后沿独立可信请求补取。资料请求先在本机settings持久登记，绑定原成本请求、工作区、月份及已确认身份，幂等登记；后台重新校验可信范围后收件，未确认持久成功不显示送达。自动伴随请求与显式补充分别选择，旧请求不能抢占手动重试。

完整证据和映射直接复用，共享仓库去重。缺失采购证据只沿已捕获的原查询筛选共用一次读取，不猜仓库筛选字段、不逐仓库拉全公司历史。资料阶段60秒、最多500次实际ERP请求、采购10页/500订单，超限保持partial/unavailable并可重试；查询子范围的所有覆盖分组都标不完整。没有改变成本公式、evidenceRef、人工优先及定稿保护。

首次fetch和JSON共用20秒硬期限，慢请求8秒提示，最多两次重试；仅400/422参数拒绝允许页大小回退。用户取消阻止新请求/后续分页，登录失效停止详情扇出。资料进度改为不遮挡成本表的可取消提示。
