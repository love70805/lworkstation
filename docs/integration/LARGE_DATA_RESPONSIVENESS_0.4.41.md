# 大数据量响应与采集异常定位（0.4.41）

目标：修复 0.4.40 数据增长后全局切页卡顿；核对已完成任务持续增长的历时展示，提供映射缺项的具体定位。实际联网核对基线 `76f6936f0ae135d3c146fa5aeeb86ec460a38d85`。

## 影响与契约

- 限定读取模型、全局后台预存检查、ERP 状态和异常展示；复用现有 IndexedDB 和收件证据，不新增业务迁移。
- 已发布成本的目录来源沿用同一已校验批次，未采用回传仍校验请求与精确 SKU/SKC 身份。身份查找使用等价索引，保持冲突拒绝、人工优先与定稿保护。
- 无自动晋升候选时，不为全局后台自动建档加载整月销售和采购历史；有候选时仍执行原有完整核验。
- 已结束的成本采集以送达时间为终点，后台采用同步不延长采集时长；部分批次映射缺项保留原始异常，不猜测映射或提升为正式成本。
- 真实现场只读核对时间、存储体积及对应异常；私有标识和详细记录仅放在忽略归档。无清理业务库、收件队列、检查点或真实数据改写。

## 验收信号

大规模同范围前后对比：全局自动检查、目录读取与切页耗时、最长主线程阻塞和内存；没有候选时无销售/采购历史读取；已发布来源避免重复校验，待处理证据仍正确校验；跨工作区、身份冲突、成本数值与参考来源一致；任务完成后计时停止、映射异常展示具体 SKU；完整测试、候选和适用发布门禁。

## 已有证据

同一 Edge headless、隔离合成数据、开发源码：47 批大体积回传 / 1000 SKU 的目录重复检查由 8667 毫秒降为 58 毫秒，最长主线程空档由 8565 毫秒降为 20 毫秒；无自动建档候选时全局检查由 9090 毫秒降为 22 毫秒，仅读成员上下文与商品。250 个自动预存商品 / 1000 SKU / 47 批的完整页面对照：首次概览读取 19009 → 2002 毫秒，最长主线程任务 17503 → 442 毫秒，商品库切页 423 → 309 毫秒。来源变化场景测量窗口内原版无长任务、修复版一次 436 毫秒长任务，后续以最终包验收收敛；该基准不是所有场景或真实账号的提速承诺。

初轮完整回归发现旧来源批次缺少 ID 时的索引键兼容问题及采用状态读取测试的旧观测方式，已修复并补跑 81 项定向测试通过；完整发布门禁与最终包验收继续完成。原始日志和只读现场分析仅存 `archive/large-data-responsiveness-20261018/`。候选、合并与公开发布分别记录。
