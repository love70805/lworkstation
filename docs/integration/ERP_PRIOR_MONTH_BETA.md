# Beta 历史三笔临时规则

2026-09-21 用户确认：核算月本身排除，只取此前月份。规则正确性尚有争议，本次仅用于 `0.3.0-beta.2`，不宣称适用于所有业务。

## 计算契约

- 数据库账本 `period` 为唯一核算月份。先排除当月及未来，再对有效采购按业务日期降序取三笔；不足三笔使用实际笔数，无记录保持缺失。
- 不优先 1688。a 表示有 1688 单号、b 表示仅采购单号，b,a,b,b,a,a 必须采用 b,a,b。
- 数量加权，Decimal 单件成本向零截断四位；异常检测仅使用合格历史证据，处置和人工更正优先级不变。
- 无时区采购时间使用中国业务时区；显式 timestamp 不得覆盖采购日期。相同时间按采购 ID、记录 ID 排序以保持可重复性。
- ERP 助手没有可信核算月份，预览不冒用采集月份作为账本月份。完整证据回传后由工作台筛选，v8.0.19 缓存 v6 不迁移旧结果。

## 采用与输出

- 仓储层从可信源证据独立计算；页面传来的成本和单号描述不能替代真实选样。完整采购证据、所选 ID 和决策版本入库。
- 旧采用成本按日期和选样复核。如果原 1688 优先规则选样与新规则不同，保留原金额并转待复核，不静默重算。兼容选样且证据充分的旧成本继续可用。
- 人工有效值仍最高优先级；冻结报告和已保存 Excel 不改写，不执行真实数据库迁移。
- 核对表展示实际参与的采购日期、单号类型、订单号、数量及单价。旧成本详情明确为“原采用”。
- 利润导出使用“关联单号”，新报告附“核算采购”明细页，逐笔记录选样和成本算法。历史报表直接下载存储文件，不拼接当前证据。
- 活跃利润缓存及成本策略版本更新，避免旧规则缓存继续显示。
