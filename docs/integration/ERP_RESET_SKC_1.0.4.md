# 1.0.4 清空后扩展 SKC 残留修复

实际远端基线：`90d30b102f4fba2cb1ab0475b78d12755ac5c8ff`。用户确认入口为工作台「数据安全 → 清空数据」。

范围：本机收件清空、ERP 扩展后台检查点/待投递缓存、页面结果/查询/任务状态。清空持久记录不包含业务标识的随机清空标记，由既有鉴权心跳和任务响应传给扩展；标记属于运行时元数据，不进入业务备份。扩展只清理自己的业务缓存，保留连接配置与登录；旧异步响应不能恢复已清空任务。正常离线和服务重启不产生清空标记，原任务恢复保持。

完成信号：隔离复现旧版残留；清空后在线页面、刷新/重启后的缓存、晚返回请求均无旧 SKC，随后新任务范围正确。按发布门禁完成前端测试/构建、桌面验证、扩展用户路径与候选实包验收后统一发布 1.0.4（助手 8.0.51）。不安装或操作用户真实业务数据。

验证：原 8.0.50 在相同隔离复现中收到空任务列表后仍保留 TASK-OLD/旧月份；修复后针对性回归通过，覆盖正常离线、后台重启、旧通知乱序、存储失败重试、任务空列表、迟到任务回复、刷新和新范围。完整前端 226 文件 / 1,790 项、23 项桌面验证和 33 项发布门禁通过。真实本机收件服务、扩展后台与 headless Edge 验证通过；中文浅深色 × 980/1440 无横向溢出。原生 ERP 和实际安装包隐藏 smoke、PR/主线 CI 均通过，四资产已核对并公开稳定；见[发布记录](../RELEASE_1.0.4.md)。必要日志、复现脚本与关键截图留于忽略归档。

发布前原依赖审计命中 Vite 与 minimatch 的构建公告。本批使用 Vite 6.4.5、minimatch 11.0.4；旧 asar/glob/dir-compare 通过小型适配模块保留 callable CommonJS、Minimatch 和解析片段接口，匹配算法仍使用官方安全实现。未屏蔽公告或降低门槛。两端 low 审计均为零。依据：[Vite 公告](https://github.com/advisories/GHSA-8g5g-mxqh-grgj)、[minimatch 公告](https://github.com/advisories/GHSA-g3hv-75wg-m249)。
