# 货号别名组、ERP 空白结果与全自动采集

日期：2026-10-10。调查基线：`origin/main 88dc6fd`，公开稳定版 0.4.17、ERP Assistant 8.0.40。原工作区停留在旧代码且有未提交内容，全部调查和实验使用托管工作树 `erp-autonomous-feasibility`。

状态：用户需求已确认，代码调查及隔离可行性实验完成，纳入下一批开发范围。尚未修改生产功能、偏好、版本或真实数据，未打包、安装或发布软件。下文的设计与验收是后续实施契约；实验通过不代表真实账号已经验收。

## 已确认的需求与当前可用办法

- 用户确认 `LBYY`、`LBY` 是同一负责人或同一组选品，应保存为一组，后续一起选择。
- 用户确认异常成本的空白位于**内置 ERP 采集助手结果表**，不是 ERP 原始采购页或工作台成本表。
- 用户要求推进只需登录、同时不影响本人 ERP 操作的全自动采集，并先确保可行。此前已讨论省略复制 SKC、粘贴、手工查询，保留正常成本自动采用、异常处理及原任务恢复保护。
- 当前输入 `LBYY,LBY` 并应用整批即可同时选择两个后缀，是新功能交付前的可用操作。当前成功选择按店铺记忆完整货号与关键词，没有持久化的命名别名组；不能把记忆旧货号等同于下一月自动覆盖全部新货号。

## 代码与实验结果

| 事项 | 已核实结果 | 实际限制 |
| --- | --- | --- |
| 货号匹配 | `importSupplierPreferences.js` 整批使用 NFKC/大小写归一化后的 `endsWith`；输入 LBYY 不会命中 LBY；显式 LBYY,LBY 同时命中，LBYX 不命中 | 短后缀也可能命中更长的字母尾；相似名称不能自动认定同一负责人 |
| 空白预览 | `result-policy.js:previewForLedger` 在月份待关联、证据缺失/不齐、无适用采购时返回空成本；原始单价缺失也可能归入无可用采购。`content.js:renderResults` 显示“—”和状态附注 | 单价 1 的完整证据会显示 1.0000 和提示，并不会仅因该异常变空；用户实际空白是哪条路径仍未取得原回传证据 |
| 前台依附 | `content.js:parseCapturedFilters` 要求采购页已捕获查询；`handleRouteChange` 会中止该文档的采集；`ensurePageSize50` 会改采购页的 select 并触发 change | 直接在用户 ERP 页自动点击不能满足无干扰要求 |
| 原生双页 | Electron 44.2.0、实际 MV3 扩展及本机收件服务在两个独立渲染页面运行。采集页未加入用户视图树；前台更换查询/店铺、输入、保留焦点及切页时，后台原 SKC/SKU 完整证据仍回传成功 | 登录与 ERP HTTP 都为合成 fixture，未验证真实账号、账号切换身份、服务端并行限制或长期资源占用；未验证可见窗口/托盘实际操作 |
| 分页修正实验 | 未改基线复现前台 20 条被助手改成 50。仅在实验扩展副本禁用 DOM 分页修改后，前台保留 20，后台 API 仍用 50 并正常回传 | 这是隔离原型，不是已交付的生产修复或完整自动启动通道 |

十种预览状态的生产函数复现，以及未改基线/禁用 DOM 分页两轮原生实验全部通过。证据在本机 `archive/erp-autonomous-feasibility/`：`reproduction.json`、`baseline/result.json`、`no-dom-pagination/result.json` 与对应脚本、日志。所有实验窗口隐藏，没有使用真实 ERP 网络、登录信息、数据库或收件队列。

架构依据：[Electron Session](https://www.electronjs.org/docs/latest/api/session) 支持同一 partition 复用会话；[WebPreferences](https://www.electronjs.org/docs/latest/api/structures/web-preferences) 支持指定 session 和后台节流配置。项目已使用 `persist:erp` 和 `backgroundThrottling: false`。这些能力及本次实验支持独立后台页方案，但不能单独证明真实 ERP 的登录机制和服务端行为。

## 1. 货号别名组

在既有整批货号选择区增加可保存的命名组，例如“LBYY / LBY”，明确列出两个别名。以后应用该组时按本批文件重新匹配全部货号，不再只恢复上个月的完整货号清单；新增货号只要符合已确认别名，就进入本次导入预览。每店保留完整货号的单独增选/排除，导入前仍显示实际命中、所影响行数和 SKC/SKU 范围。

- 组按工作区隔离，名称、明确别名及匹配方式可编辑；默认沿用末尾匹配，并可明确选择包含或完整货号匹配。只做匹配归一化，不改原货号、SKU 或 SKC。
- 两个别名同属一组是用户已确认的业务事实。其它近似尾码可以提示，但不凭编辑距离、共同子串或删除重复字母自动加入；特别检查短尾码与较长字母尾的交叠，显示歧义候选并允许完整货号排除。
- 增加“未命中”核对视图；本次识别到的新别名只给建议，用户明确加入后才成为长期规则。已确认别名下的新商品不需要逐个重新定义组。
- 使用新的偏好版本保存组与组引用，兼容读取现有 v2/v1 成功选择。失败/取消导入不得悄悄替换成功偏好。不得改旧存储格式或混用 `matched` 作为负责人归属证据。
- 不补写历史台账；重新导入/更换完整月范围继续使用现有替换确认、原子提交及导入版本保护。

涉及：`importSupplierPreferences.js`、整批 `ImportPreview.jsx`、`ImportSupplierPicker.jsx` 及对应导入样式/测试。验收涵盖 LBYY+LBY、LBYX、交叠字母尾、大小写/全半角、多店例外、下月新货号、未命中与零命中、取消/失败、旧偏好、完整月替换。

## 2. ERP 结果表不以空白代替原因

在成本单元格直接显示明确状态和下一步，保留原金额与采购证据入口。已有“月份待关联”“采购历史未读齐”等附注应前置，不把所有空成本称为价格异常。

| 实际状态 | 用户应看到的内容与动作 |
| --- | --- |
| 价格异常且待核对 | “疑似异常，待核对”，可展开原采购单价/日期/数量与原因；正式成本未通过前不冒充已采用 |
| 原始价格缺失/非法 | “采购单价缺失/无效”，定位被排除的采购明细，不用零补空 |
| 采购证据未齐/映射不齐 | “证据未齐”，展示失败目标及重试范围 |
| 仅后续月份采购或取消记录 | “该核算月份无有效采购”，显示月末边界及排除原因 |
| 尚未关联账本月份 | “待关联核算月份”，引导回当前账本，不使用系统月份猜测 |
| 已送达但没有本地预览 | 明确“已送达，当前无本地预览”并指向工作台记录，保留回执，避免引导重复全量采集 |

详细原因从现有 `purchaseRecords`、`excludedDetails`、目录/映射失败、预览状态及可信接收结果派生。来源不明时显示“原因待核验”，不猜测。工作台正式异常算法保持权威，不能在扩展另写一套阈值后宣称两端一致。若必须跨桥接新增字段，先追加可选诊断契约及过滤/限长回归，不能以显示状态放松采信条件。

确保范围内目标可核对：当前已有档案占位行；未能建立映射的目标需在缺项区列出平台 SKC/SKU，不伪造仓库关系或采购成本行。真实零值与微小正数按既有规则保留，异常状态不能使目标消失或把缺失填为 0。

沿用已有配色、键盘与展开方式，文字说明不只靠颜色。关键错误用现有可访问状态区，并关联具体行；窄窗口、中文、浅深色检查不改现有核算和人工更正流程。

涉及：扩展 `content.js`、`result-policy.js`、对应 CSS 与桥接契约/测试；必要时扩展已有可信回执投影。验收覆盖表格/搜索/分页/展开/CSV、缓存恢复、正常与异常混批、真实零/微小值、人工优先及定稿保护。用户实际空白至少回读一例原始回传，确认提示覆盖其真实路径。

## 3. 全自动采集：独立后台页共用登录

目标流程：**已确认的台账导入与货号范围 → 建立固定采集任务 → 等待 ERP 登录 → 独立后台页自动采集 → 逐批回传 → 正常成本自动采用，异常集中核对 → 补资料**。省掉人工复制、粘贴范围和采购页查询；用户日常 ERP 标签用于自己的操作。

自动模式只针对已导入、已确认的账本范围。初次启动请求等待登录时，登录完成可自动接续；不能仅因登录扫描其它月份/店铺。用户主动暂停或停止、旧任务重启恢复继续遵守已有明确操作语义，不以“自动”撤销用户停止。若以后要求改变旧任务的恢复语义，再单独说明该部分行为。

### 必须补齐的实现契约

1. **视图与会话**：新增按需创建的采集 `WebContentsView`，复用同一 ERP Session；不导航、刷新、修改用户页面的表单、分页、滚动或焦点。采集分页仅在 API 参数上设置。后台页不加入前台视图树、不打开外部窗口；终止/闲置后释放，并检查内存及连接占用。远程页的 sandbox、contextIsolation、webSecurity、域名/导航白名单继续有效。
2. **启动通道**：可信工作台经受控桌面 IPC/本机任务服务生成启动命令。必须校验主框架来源、工作区/账本/导入版本、唯一 requestId 与不可变平台 SKC+SKU 快照，不能让任意 ERP 网页消息启动任意任务。命令幂等、有明确领取与回执，重复触发复用活动任务。
3. **查询初始化**：从当前 ERP 支持的页面/只读接口验证必需字段、权限和登录，无需人工查询；不得猜测接口必填条件或借用前台用户临时的店铺/日期/状态。固定任务查询仅增加允许的目标过滤，保留空参数契约及全部历史证据。不会因为货号组扩大为同 SKC 的未售变体。
4. **账号与共享状态**：同 Session 也会共享 localStorage、扩展 storage 和 Cookie。本次发现 `erpAssistantV8_latest_cost_result_v7` 是同源全局结果缓存，`latestExtension` 是最新单记录；须按工作区/任务/采集角色隔离结果快照和状态，防止后台结果覆盖前台预览、前台心跳误报后台就绪。账号/组织身份不能从 Cookie 存在推定，切换账号或登录失效必须停止旧账号在途任务及拒绝迟到结果，凭据不进入业务存储或日志。
5. **唯一执行与限流**：一个任务只允许一个采集执行者，复用现有 task/attempt/lease；前台助手手工采集要与后台协调，不能让两个执行者各自再占 8 路。保持每批 20 SKC、现有全局请求上限、分页/重试/维护暂停。前台人工 ERP 操作也会占服务器资源，需要真实响应时间与失败率测量，发现限流或明显争用时后台退让。
6. **回传与安全**：采用当前完整证据校验、月份边界、精确 SKC/SKU、正常逐项自动采用和异常隔离。人工有效值保持最高优先级，定稿不改；显示状态与真实采集/送达/采用分开。导入版本变化使旧命令失效；暂停/停止立即停止新增读取，重试保留历史尝试与幂等回执。

涉及：导入完成/成本页启动入口、workspace preload/IPC、桌面 remote view 生命周期与状态、本机任务服务、扩展后台/内容脚本/缓存及现有 domain contract。新增持久化字段须先更新服务及前端可选字段契约；如需要数据库迁移只能追加版本，隔离验证后按规则处理真实库执行。

### 可行性与交付门槛

- **已通过：架构和核心路径**。两个真实 Electron 页面/原生扩展共用隔离会话，后台从固定采购条件读取、映射并回传；前台同时更换查询及页面不影响该任务。停用 DOM 分页修改后，前台分页保持、后台仍用原 API 分页。无可见窗口。
- **待实施验证：产品完整链路**。可信自动启动、无需捕获人工查询、任务/角色缓存隔离、重复启动、租约冲突、跨工作区/导入版本/账号切换、登录等待/失效、暂停停止和恢复、接收器落库及人工/定稿保护、资源回收与长时间空闲。
- **待真实登录验收：可用性**。在用户登录的受控隔离候选中验证真实页面与会话/权限、采购参数、HTTP/Cookie/必要页面状态、并行前台操作的页面/焦点/分页/输入无改写，测量限流与操作延迟。读采购接口，不改 ERP 订单。不能用合成 HTTP 或隐藏窗口结果代替真实账号和真实可见交互通过。

实施顺序：先统一固定任务/缓存/角色契约，再实现别名组与空白原因显示，接通独立后台页和可信自动入口，最后做合成故障回归、真实账号并行验收及整批候选。三笔提前停止、更高并发、总批次物理合并不属于本批，不改变异常检测需要的历史证据。

同一批准范围完成后统一执行前端全量测试/build、适用 desktop verify、实际用户路径与候选 smoke、中文/浅深色/窗口检查、PR/main CI、稳定打包发布及公开资产回读；在真实自动采集可行性未通过前，不宣称全自动可交付、不发布未经验收的自动功能。本轮是调查/规划，没有软件版本或本机安装。
