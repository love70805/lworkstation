# 0.3.0-beta.5 · 流程一致与本机缓存

当前状态：实现完成，正在最终回归与候选验收，尚未公开发布。仅 Windows Beta 通道；稳定版保持 0.2.19。本机不安装，不修改真实业务数据，不新增数据库迁移。

## 使用变化

- 导入、成本、报告沿用所选账本月份；取消或完成回到原页面与店铺。无效账本明确提示重选，不自动切换月份。成本仍以台账月份为准，采用当月及以前最近三笔采购、数量加权、四位截断。
- 首页下一步、利润缺成本与报告准备度使用整月状态。人工已处理的异常不再阻塞同批其它合格 ERP 成本；采用动作重新检查完整请求和所有相关店铺，后续回传不能覆盖人工值。已采用、待处理、尚未收到成本分别显示。
- 报告准备区可直接处理缺成本、代发和店铺扣款，下载当前文件或查历史。概览和账本使用与当前基础、扣款批次对应的财务结果；扣款换版时明确待生成，基础重开后不沿用旧利润，历史文件保持原样。
- 商品编辑与批量状态使用一致保存规则；草稿按钮不能绕过正式商品检查。参考预览跟随当前报价，售价空值与真实零值区分，标签正常保存；未保存离开可取消，处理后返回保留筛选与位置。
- 侧栏“系统与备份”直接打开系统检查，页内可切换数据备份。桌面备份仅在真实文件落盘后确认完成；取消或失败不会继续执行受保护的恢复。更新下载可取消和重试，关闭偏好与托盘行为一致。
- 页面加载、失败、空结果分别显示；局部重试不把读取失败当作正常空数据。销售详情键盘进入与返回、利润/成本往返展开位置、多位数输入、窄窗口操作与侧栏切换得到修正。

## 持久缓存与测量

修复启动时相同成员上下文重复写入导致缓存失效，以及销售 liveQuery 内派生缓存无法落盘两处问题。仅将可重建的派生缓存写入放到独立异步任务；业务读取继续受只读限制，来源变化会拒绝过期结果，缓存故障不阻塞正确计算。

同机 Edge 隔离数据、两轮测试，单位毫秒（完整页面可用时间）：

| 十万行场景 | 原基线 | Beta.5 |
| --- | --- | --- |
| 关闭页面后重新打开首页 | 2647–2820 | 1724–1770 |
| 关闭页面后重新打开利润 | 2470–2985 | 1856–2154 |
| 已加载后返回同月首页 | 129–145 | 130–131 |
| 已加载后返回同月利润 | 164–181 | 197–198 |

一万/十万行重开均没有重新启动计算 Worker、没有重复写成员设置、来源版本保持相同；单 SKU 更正后利润正确更新。十万行首次首页约 2678–2741ms，单项更正完整路径约 3099–3184ms，本版没有承诺首次加载或更改后立即完成。

限制：重开仍要读取十万行原始台账（约 795–812ms），聚合缓存读取约 12–14ms；当前全局来源版本仍会让单店成本更正触发其它派生结果重新计算。本版未改造全部依赖失效策略。原始数据、方法和两轮结果：`archive/beta5-performance/`。
