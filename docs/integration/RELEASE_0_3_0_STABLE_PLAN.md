## 基线与范围

### 发布前追加开发：以 ERP 为主的商品档案预填

用户追加授权开发选品参考中的已使用成本商品建档。通过既有“建立档案→编辑→保存”入口，以 ERP 为主要商品资料来源，台账仅交叉校验/补缺；不默认自动入库或批量写真实库，正式发布仍暂停。

2026-09-28 后续授权“批准进行测试”，决策端已只读观察采购详情成功响应并提供脱敏字段定位。追加可选 `purchaseCatalog`：`picturesLinking`/`pictureLink1688` 图片URL，采购规格/型号、仓库规格/颜色、原始采购比例、采购明细/订单/行号、供应商ID及采购行barcode，严格14字段白名单。实际图片解析优先仓库图，再采购图；按明细与仓库关联，显式barcode须匹配可靠平台映射。采购规格单独展示，不当作平台属性；比例 `1-1` 展示为 `1:1`，不参与SKU推断或成本/报价换算。贯通扩展、envelope、持久化、重开与显式建档保存，使用真实字段形态的脱敏合成fixture验证；不再操作用户采购页面，不写真实数据或发布。

跨仓库辅助SKU的纯资料白名单追加保存在既有 `erpCostBatches.sourceContract.catalogRows`，来源必须是已验证完整回传，剔除价格/数量/正式成本。参考快照通过独立 `erpCatalogRows` 投影读取，仅当前工作区有效published批次、存在账本且登记请求的工作区/账本/查询SKC匹配；子行须绑定父batchId/ledgerId/workspaceId，子行查询范围不能扩大父请求。带批次的历史成本行增加只读目录资格检查，撤回后保留财务历史但不再自动补档；无批次旧行保持兼容。对应仓库证据的映射失败警告合并保留，异常辅助关系不阻断健康正式成本。无需schema迁移，回传后重开可带齐同SKC跨仓库SKU，台账仅有一个SKU时也不丢辅助资料。验收同时断言建档完整与aux正式成本/报价没有增加。

契约新增可选 `imageUrl`、`attribute`、`catalogMappings`（完整平台 SKU/SKC/仓库SKU及白名单商品字段）、逐笔 `supplier1688Links`（商品/店铺用途）。贯通 canonical 扩展→envelope→ERP成本行→参考投影→编辑草稿；无需改变 v15 表结构。ERP 正式成本仅展示关联，不写入供应商报价，月度计算、人工优先、完整采购证据及定稿不变。

一次带齐目标可信 SKC 全部 SKU，人工档案优先且只补缺，阻止重复/跨工作区/冲突归属；占位文字不是商品名。供应商名称/URL/SKU保留同一采购来源，多来源和冲突可核对。测试用隔离库覆盖回传后重开、点击建档、保存及参考一致性。

真实字段定位已由决策端只读核实采购管理页面及 `/purchase/purchase/v1/purchase-order-details` 成功响应的 `data[]`，未保留原始业务响应、凭据或真实图片。`itemId` 是仓库SKU，`tradeName` 是商品名；`picturesLinking`/`pictureLink1688` 为图片，`purchaseSpecificationAndModel1688`/`model1688` 为采购规格/型号，`purchaseProportion1688` 为采购比例。采购明细ID、订单ID/号、行号和供应商ID来自同一行；`productLink1688`/`purchasingLink1688` 是商品链接。DOM图片/规格/供应商必须限制在对应行，重复供应商ID不得跨行借用。已按这些实际字段映射更新解析器，并用合成值验证完整链路。

观察样本的 `barcodeSkuid`/`barcodeSkcid` 为空，平台SKU/SKC继续以商品平台映射为准，不能从 `itemId` 或采购比例推断。`specificationAndModel`/`productColor` 在样本中也为空。采购规格以独立证据展示，只有明确平台属性来源或有效台账补缺才预填平台属性；人工值优先。更新后的8.0.23扩展尚未在真实账号重新采集，当前隔离通过不能代替该项实测。
