# 0.4.9 清空本机数据与 ERP 历史残留

基线：2026-10-08 已核对的 origin/main `0f7c4d1` / 稳定版 0.4.8。用户反馈清空本机数据后仍显示历史核算任务。

## 根因与契约

清空入口只清理 IndexedDB；桌面收件文件中的请求、分批任务、成本/资料回传及租约仍存留。同一工作区月份的账本 ID 可复用，重导入后会查询到旧任务。浏览器成本草稿也属于本机业务数据。

- 显式确认“清空本机数据”后，暂停并等待工作台后台收件/恢复结束，再通过可信主框架 IPC 清理本应用收件业务记录，清理成本草稿，最后原子清空业务表并创建 CNY 空白默认工作区。
- 桌面收件清理需要仅宿主持有的独立能力凭据；ERP/1688 扩展、远程网页和子框架不能调用。清空的是本应用本机所有工作区的业务记录，与现有 IndexedDB 全表清空范围一致。
- 请求、分批任务、待处理及已处理回传、任务租约一并清理；保留连接状态和工作区连接上下文，不改变 ERP/1688 登录会话、桌面偏好、更新设置、外部备份或其他应用数据。
- 旧 ERP 任务、续传和迟到结果因请求/任务不存在而拒绝；不会重新写入已清空账本。新的同月账本可以登记新请求和新任务。
- 收件清理或草稿清理失败时不清空 IndexedDB，不报告成功；允许重新尝试。跨存储操作不能提供单一事务，较早阶段若已完成，后续失败须明确报错。
- 不新增数据库迁移，不改变成本计算、人工优先或定稿口径；不自动操作真实数据或安装。

影响：workspace repository、后台收件生命周期、成本草稿、desktop preload/可信 IPC/收件控制器、ERP 本机服务。公共业务 envelope 不变。

## 验收信号

隔离数据覆盖已有定稿/人工成本/旧请求/运行与停止任务/成本及资料回传/租约；清空后业务表和收件历史为空，重启与同月重导入仍为空；旧任务/结果拒绝，新请求正常。验证后台正在收件、存储失败、非可信调用及非桌面环境。完整前端测试/构建、ERP 发布门禁、desktop verify、隐藏最终候选和实际清空用户路径通过后统一稳定发布，公开资产回读另记。
