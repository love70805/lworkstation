# ERP Assistant Chrome 扩展

## 安装

1. 打开 Chrome 扩展管理页 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择解压后的 `ERP-Assistant-v8.0.35-shopeers-bridge` 文件夹。
5. 刷新已打开的卓麟 ERP 页面。

## 运行准则

- 扩展在卓麟 ERP 的 HTTPS 首页、其他页面和采购管理页面启动，不读取无关网站。助手已加载、工作台连接和采购查询条件分别显示；登录页须先登录，其他页可点击“打开采购管理”。
- 桌面版启动后在后台自动检测，停留工作站也能通过左上角小灯获知状态；悬停或聚焦显示原因，点击可查看详情并重新连接。已确认助手通信和登录后显示绿色，首次就绪轻提示一次。登录未确认、需登录、断连或过期不会显示绿色。登录确认只观察 ERP 原本发出的合法会话接口响应，不为检测额外发起采购查询，也不缓存登录凭据。
- 每个 ERP 标签页只保留一个“ERP 成本助手”入口；采购管理在 iframe 中时，入口打开当前可见采购页的成本面板，不重复添加浮窗按钮。ERP 重建页面内容、SPA 切换或返回时，入口自动恢复。
- 只有采购管理上下文允许预览月份读取、采集回传与手动重试；离开采购路由会取消正在读取的任务并清除当前查询快照，不在其他页面重用旧条件。扩展后台独立保留待投递证据，按原有工作区绑定与重试上限恢复。
- 用户先在采购管理页执行查询，扩展使用该次查询的完整参数进行核算。
- 本版仅随 Beta 使用临时口径：采购记录按时间从新到旧取最近最多 3 条，不区分 1688 与普通采购类型，按数量加权。类型顺序为 b,a,b,b,a,a 时选 b,a,b，不优先或补齐某种类型。
- 表格及 CSV 按相同顺序列出全部入选记录的采购日期、单号类型与单号；混合采购不会标为纯 1688。CSV 单元格内每行对应一条入选记录。
- 保留全部有效采购证据。扩展通过隔离后台读取工作台已登记的台账月份，先保留台账当月及以前采购，再取最近三笔，数量加权后四位截断。未取得唯一可信月份时显示“台账月份待关联”，不使用系统日期或展示无月份汇总成本；完整证据仍会回传。
- Lworkstation 使用可信账本月份，包含账本当月及以前采购，排除后续月份，在合格有效记录中按时间取最近 3 条，再核对并采用正式成本；跨年同样适用。此 Beta 临时口径不代表稳定版规则变更。
- 付款状态或 1688 订单状态为“已取消”的订单、已作废订单、无效日期、非正数量和无效单价不参与预览。
- 采购单价为 0 或 1 时仅显示疑似异常提示，扩展不修改价格、不确认正式成本。
- 疑似异常不会阻止预览、复制、CSV 导出或自动回传；修正、确认和正式发布由 Lworkstation 利润核算页负责。
- CSV 导出对公式或控制字符开头的文本添加前导单引号，包含前导空白与全角公式符号；成本数值、缓存和回传原始证据保持不变。此处理用于本次导出的表格查看，不保证表格软件编辑并重新保存后的文件仍保留文本标记。
- 回传数据包含同仓库 SKU 的全部有效采购记录、最近三次预览依据、作废/取消/无效排除证据与来源元数据。
- 采购列表分页失败会停止本次核算，避免把缺页数据当成完整结果；单笔明细或平台映射失败会作为不完整证据明确标记，仍可预览、复制、导出和回传，但 Lworkstation 会阻止其直接发布为正式成本。
- 工作台自动登记当前账本与筛选范围；允许非空 SKC 子集分批查询，同范围重复采集使用新的投递标识。
- 自动回传使用稳定的 `resultDeliveryId`；后台独立保存失败证据，自动重试有次数与时效上限，终止后仍保留证据。可点击“重试回传”；过期或缺少工作区快照时须重新采集。
- 本机服务接收成功后，“复制成本”优先复制当前批次完整 JSON；否则复制 TSV 预览。CSV/TSV 不包含完整采购证据，不能直接发布为 ERP 正式成本。
- 8.0.23 保留 v6 页面结果缓存，恢复时重新获取可信月份并用完整证据复算预览，不信任缓存月份或缓存汇总单价；不读取旧 v5/v4 结果。后台待投递证据不因页面缓存升级而删除，旧证据是否可采用仍由工作台校验。
- 平台映射候选与采购明细中的商品资料随证据保留，供应商名称、商品链接与店铺链接按各笔采购来源配对；缺失链接不会借用另一供应商的链接。商品档案仍由工作台编辑保存，不自动创建或改写正式成本。
- 采购详情图片优先使用仓库图，再使用该明细的 1688 图片；明确的平台条码限制资料归属。多个平台 SKU 共用仓库但没有明确条码时，1688 采购图保留为采购参考，不当作每个 SKU 的专属图片。
- 采购规格、颜色和采购比例单独保留，不自动变成平台 SKU 属性或改变采购数量、成本单位。商品链接来自本条采购明细；不会按同名供应商从其他明细、订单商品链接或页面链接补入。

## 8.0.24 资料补充

- 工作台登记已确认平台 SKC 和 SKU 的资料请求后，在 ERP 采购管理助手点击“补充资料”，按该请求一次读取；无销量分支可保留为资料待编辑。多个有效请求时先在工作台取消旧请求，避免选择不明确。
- 普通成本核算在本次用户操作内同步目录、映射、图片和供应商来源。商品分页按 page/limit 和 count 完整覆盖，映射按返回 count 检查全部记录，仅保留目标 SKC 的准确 SKC—SKU—仓库对应。共用仓库不会扩大到他人 SKC。
- 五组覆盖信息分别记录目录、映射、图片、供应商与采购证据的成功、缺失和失败；不完整 optional 补取不会覆盖已有完整成本证据或映射。
- 后台经已配置工作区与 capability 回传现有本机 127.0.0.1 inbox，页面不能指定远端地址或凭据。仅资料包独立接收并持久保存，不触发正式成本采用；已收集结果沿既有次数与期限有限重试，状态心跳不读取 ERP 业务资料。
- 供应商名称和各笔采购的 1688 商品/店铺链接保留准确来源，多供应商名称不任意配对链接。平台属性只用可读平台映射字段，仓库规格、采购规格和原始比例仍为独立证据，无已验证换算关系时保持缺项。

## 开发校验

## 8.0.29 当前采购表单兼容

补齐官方采购查询中的商品名称、异常状态、采购人、账号名称、采购/创建类型、相邻供应商与排序等字段，包含表单默认空值；正常查询不再因恢复快照字段不支持而停止。快照保留已捕获条件用于恢复核对，未知条件仍明确拒绝。正式成本沿工作台当前登记的 SKC/SKU 范围读取目标完整采购历史，保留店铺条件，展开时间、商品名称、异常/采购状态等临时展示条件。台账完整入库与工作台筛选互不影响。

旧版扩展须在扩展管理页重新加载新版目录并刷新 ERP 页面；仅升级工作台不能更新 Chrome 中已加载的外部扩展。原始请求绑定、取消单排除、证据完整性、人工成本和定稿保护不变。

## 8.0.28 本机任务恢复

- 刷新页面、重新打开或重启浏览器后，成本预览可显示“继续未完成采集”。恢复前重新核对工作区、月份、请求及完整目标；查询条件改变时要求重新采集。
- 任务检查点由扩展后台保留 24 小时，最多八项、合计 1 MiB，只保存必要范围和进度，不保存登录凭据。账号或采购历史版本无法确认时重新读取目标，不把旧页当作当前完整成本；部分目标每页重新核验。
- 本版按用户确认的固定 ERP 账号使用范围交付。恢复会重新读取当前会话；尚无跨账号识别，不能声称原账号已核验或跨账号恢复已通过。
- 开始采集时保存工作台登记请求的规范快照，绑定工作区、账本、月份、登记版本及完整 SKC/SKU。首次回传必须找到同一未完成检查点并重新核对登记，不能随当前工作区重新匹配；保存失败、过期或范围变化时停止。未取得请求上下文仍可本地预览、复制和导出，不自动回传正式成本。
- 已保留载荷沿原请求和投递身份重试；已送达的相同载荷由持久回执识别，变化的载荷不能覆盖原身份。部分结果送达后由后台分配后续采集身份。
- “读取中 / 待继续 / 已送达”与“待工作台采用”分别显示。送达仍使用既有持久确认，成本先完成，可选图片资料随后补充。同一页面再次继续也重新核验；只有本次未中断读取内部可复用刚取得的证据。
- 检查点不足、过期或失效不改变正式利润；用户仍可重新查询。扩展本机保留不是云端同步。

## 8.0.27 全量目标与续取

关联台账后以已登记完整 SKC 集合逐目标查询，页面搜索不缩小采集范围；同目标采购去重，保留店铺与月份关联，不扫描全公司。采购分页取消10页/500单限制，以实际分页终点与总数一致性验收；重复页、总数变化、登录失效明确停止。成本阶段每次最多5分钟，已成功页和逐单明细在本页面会话保留10分钟，重新核算直接复用已读齐目标，未读齐目标先校验首分页再续取；来源变化或缓存不可用时重新读取。仅本批请求、查询范围及月份一致时复用采购页；未完成不回传完整成本，也不替代已有有效证据。

成本先回传，可选资料独立执行60秒预算并可补取，完整仓库证据复用；未售规格仍按同SKC映射建档，不新增月度收入。requestId、evidenceRef、原收件幂等与人工成本／定稿保护继续沿用。旧版本下载保留，下方8.0.25/8.0.26段落仅记录历史规则。

```powershell
node --check integrations/erp-assistant-extension/src/content.js
node tools/erp-csv-export.test.mjs
node tools/erp-result-policy.test.mjs
pnpm --dir frontend erp:bridge:test
```

## 8.0.25 采集恢复

成本证据先完成显示及回传，商品资料沿独立已登记请求补充。资料最多60秒，可取消且不会遮挡成本结果；完整映射/采购证据复用，共享仓库不重复读取。采购补取只使用已捕获查询范围，最多10页/500订单；超过预算标记资料不完整，缩小查询后可重试。首请求及JSON读取每次最多20秒，慢请求、重试和登录失效分别提示。送达只以本机持久收件确认显示。

## 8.0.26 完整历史与取消状态

成本沿捕获的目标 SKC 查询，将时间范围扩展为“全部”，解除日期、采购状态等展示筛选，保留目标与店铺范围。资料中缺失的已验证仓库商品，按其仓库 SKU 单独补取；同仓复用，不扫描全公司。每次历史读取最多10页/500单，保留完整计数校验；不完整时不展示成本或假报缺少采购，需分批选择更少商品或重试。资料60秒期限、请求期限、登录及取消保护延续。

已核实 `purchaseOrderStatus1688=4` 为取消；仅具体1688状态字段的4排除，其他状态字段的4保持有效。订单状态带入明细及排除审计，ERP作废11、取消文字也排除，被排除采购不占最近三笔名额。采购数量与单价已按仓库入库件数记录，规格比例不参与乘除或阻断。旧预览缓存失效，旧业务证据缺失状态不自动推断、修改；不更改真实库、人工更正或定稿记录。

## 8.0.30 按当前查询重新采集

重新核算在已有任务时明确确认，从零重读并生成新投递身份。旧待送达载荷保留；继续未完成采集仍校验原查询。兼容保留 8.0.29 的有效检查点，不因本次补丁升级清空任务。

## 8.0.31 打开预览前检查原任务

打开成本预览先读取包括已完成任务在内的检查点，已有任务时提示继续或重新核算，不自动覆盖原查询。列表延迟及并发写入保护保留；兼容保留 8.0.29 / 8.0.30 有效任务，旧待送达结果不清空。

## 8.0.32 检查点查询字段顺序修复

保存与恢复时对新旧查询统一归一化，避免 Chromium 本机扩展存储重排字段造成误报。真实条件变化仍拒绝继续旧任务；保留 8.0.29–8.0.31 的有效检查点和待送达结果。

## 8.0.33 核算目标解析修复

兼容正式请求中的平台 SKC 标识对象，查询时提取原始 platformSkc 字符串，保留原始大小写；避免发送 `[object Object]` 后全部返回空结果。旧有效任务保留，继续采集会重新读取目标证据，空结果仍拒绝作为成本投递。

## 8.0.34 大批量采集等待时间

成本采集上限由 5 分钟延长至 60 分钟，补充资料由 1 分钟延长至 30 分钟；单次 ERP 请求由 20 秒延长至 120 秒，仍最多重试 2 次。可随时取消，登录失效立即停止；达到上限或未完成的证据不会变为完整正式成本。资料请求次数保护仍为 500。保留 8.0.29–8.0.33 有效检查点及原待送达证据。

## 8.0.35 分批采集与本机恢复

成本默认每批 20 个 SKC，采购列表两路、ERP 请求全局最多八路。各批独立回传，先成本后资料；60 分钟成本与30 分钟资料时限按批执行，单请求120 秒。取消资料全任务500次请求上限，分页与证据完整性保护保留。暂停停止新增读取，停止中止未完成请求；重启后用户点击继续，先核对已送达回执，未完成批次重新读取。工作台显示已采集、已送达及实际已采用数量，展示筛选不改变活动任务。兼容旧成本包和8.0.29–8.0.34有效检查点，不将旧检查点推断为完成批次。外置 Chrome 扩展需更新并重新加载；内置扩展随桌面 v0.4.3 更新。
