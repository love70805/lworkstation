# 0.4.19 现有核算与备份可靠性修复

日期：2026-10-12。基线：远端 main `f56dc28867218c28caa22d158d36e7ff9db5f58b` / 0.4.18。用户在审查后明确要求“先优化修复现有代码”。本批只实施已复现的五项问题，按既有授权一次性稳定发布，本机不安装，不操作真实数据库或收件队列。

## 范围与契约

- SKU/SKC 归属：同一账本内同一规范化平台 SKU 的多 SKC 冲突不得被正式成本覆盖率或报告定稿当作已完成。正式 ERP 成本与台账双方已知 SKC 不一致时失去当前核算资格；合法历史成本缺少 SKC 时保持既有资格，不猜测或补写归属，新回传仍受完整 source contract 校验。校验放在共享领域及持久化边界，页面显示可处理原因；不修改已有定稿快照，人工有效值和真实零/微小值保护延续。
- 备份恢复：与既有后台任务协调共用互斥边界，恢复前禁止新后台周期并等待在途工作结束，落库校验原工作区；恢复成功或失败后均能正常继续。恢复不删除真实桌面收件历史，不改变用户暂停/停止语义。
- 备份完整性：校验声明记录数、按数据库版本要求的表和新增备份清单。合法旧备份可缺少后续版本新增的表；损坏的同版本备份在任何写入前拒绝。数据库版本迁移保持不变。
- 业务筛选配置：将命名货号组、上次应用组、逐店例外及对应导入筛选配置纳入明确白名单备份契约；不打包账号、登录、Cookie、Token 或其它任意 localStorage。跨工作区配置隔离，失败不得显示恢复成功。旧格式不应静默清掉尚未包含的现有偏好。
- 首页待办：`pendingLedgerTasks` 只投影账本 id、月份、任务类型和缺成本数，按月份先后覆盖当前工作区全部未冻结账本。未校验过的旧非空账本按财务来源版本缓存只读覆盖率，避免继续显示错误 ready，不持久改写。较新草稿不能遮掉较早待确认利润；默认展示前三项，余项可展开，总数包含全部任务，入口自带对应账本月份。

独立后台自动采集、自动备份调度、利润差异分析保留为后续方向，不进入本批。

## 文件职责与协作

- 核算修复：成本覆盖、归属领域合同、利润报告及必要 repository / 成本页面提示和回归。
- 备份修复：workspace repository、备份格式、业务配置白名单、后台互斥与采集落库归属校验及回归。
- 主线：首页待办领域/页面、整合审查、版本元数据、构建、候选与发布；涉及 `workspaceRepository` 的待办缓存版本修改等备份任务交付后串行执行。

## 验收信号

1. 复现的追加冲突 SKU/SKC 导入不再显示可定稿，直接调用保存报告亦被阻断；修正来源后恢复，正常跨店同 SKU、人工成本、真实零/微小值和冻结报告不回退。
2. 旧工作区 A 在途采集与恢复 B 交错时不跨工作区落库或误确认；恢复失败回到可重试状态。
3. 同版本删表/总数或清单不符恢复前失败，历史版本兼容；新备份换机可恢复货号组及筛选，非法配置与写入失败可识别。
4. 多月份、较新空草稿、较早 ready、缺成本、关闭及跨工作区场景下待办数量和目标正确。
5. 前端全量测试/build、完整发布门禁、desktop verify、无头用户路径和浅深色窗口布局、隐藏桌面候选 smoke、包内输入一致性、PR/main CI 及公开资产回读通过后发布。
