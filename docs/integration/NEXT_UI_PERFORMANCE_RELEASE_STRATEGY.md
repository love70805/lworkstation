# 下一稳定版更新策略：整体 UI、销售对比、动效与加载性能

状态：2026-09-15 已随 0.2.16 交付并公开发布，详见 [验收记录](../RELEASE_0.2.16.md)。下方为规划依据，具体性能与边界以验收记录为准。

## 发布方式

同一版本统一交付，内部按依赖拆分实现与验收，不按每个 UI 小改动单独发版。功能通过完整验证后，按用户已有自动发布授权完成 PR/CI、Windows 候选、GitHub 稳定版和公开资产回读。本机继续暂不安装。

用户已授权按最合适的协作方式继续开发，本轮交付完整软件更新。云端部署不纳入本版，设计保留未来同步的工作区与版本边界。

## 更新范围

### 1. 全局 UI 与日常操作

- 统一中文字体层级、间距、颜色语义、表头、斑马纹、数值对齐、筛选和按钮层级，保持桌面适度密度。
- 覆盖经营概览、选品、利润/成本核对、月度账本导入、代发/扣款来源、报告和诊断页面；沿用已有业务职责及 Excel 模板。
- 简化重复标题、入口和说明；长列表/证据按需展示，表格操作与主要按钮在窗口化时可见。
- 翻页后回到目标列表第一行；搜索或改变日期/店铺后重置页码；从详细页面返回恢复原筛选、页码和位置。
- 编辑输入保持焦点；小确认、小编辑和复杂导入采用相应大小；异常原因和下一步处理可直达。

### 2. 每日销售及不同月份对比

- 普通全月视图按店铺颜色分段，只显示简短店铺图例，不常驻每一天/每店的大量金额。
- 点击日期后，窄区显示一根当天分段柱，段内显示店名和当前指标占比；宽区显示当天商品明细。删除柱子下方重复店铺详情，悬停/聚焦显示金额、销量和占比。
- 店铺颜色跨日期和月份一致，不因排序/过滤重新分配。常规操作有店铺文字，不能仅靠颜色判断。
- 全月绘图区以 200–240 CSS 像素、当天绘图区以 180–200 CSS 像素为初始目标，按可用窗口校验。高度指绘图区，不是整个销售面板。
- 保留零基线；纵轴按当前指标和范围内的单日最大值取合理上限，不使用月累计作为上限，不添加参考线，不修改原数据来拉开差距。
- 新增可选对比月份。默认单月，开启后两个月图表并排；空间不足时上下排列。
- 两个月使用同一店铺范围、指标、颜色和纵轴；按日号对齐悬停，显示两个月该日的金额/销量和差额；点击明确进入所点击月份的当天明细。
- 只常驻必要的月份销售额、销量汇总。月份天数差异、未发生日期和缺失数据留空，不当作零；未完月份注明统计截止日期，不冒充完整月比较。日期口径沿用台账添加时间。
- 分店铺对比时区分“该店不存在于本月来源”和“已知销售为零”。负金额与零净额保持原值；无法合理表达为百分比时显示金额/数量及适用提示，不输出误导性占比。

### 3. 动效作为独立交付项

目标是类似 iOS 的简约、连续、细致反馈，沿用本产品样式。

| 场景 | 预期行为 | 初始时长 |
| --- | --- | --- |
| 按钮按压/悬停 | 轻微压缩、颜色反馈，命中区域稳定 | 80–150 ms |
| 全月进入当天 | 所选柱与当天柱有位置延续，明细顺滑出现；不让用户等待动画结束才能操作 | 220–300 ms |
| 返回/切换页面 | 保持空间关系，短距离位移与淡入，退出更快 | 160–240 ms |
| 弹窗 | 轻微缩放与位移，标题和操作位置稳定 | 180–240 ms |
| 切换店铺/指标 | 数据先切换到正确状态，图形平滑过渡；避免数字反复滚动计数 | 180–260 ms |
| 浅深色 | 表面与文字自然切换，避免大面积模糊和全页持续重排 | 160–220 ms |

- 不使用循环漂浮、磁吸按钮、夸张弹跳或长时间交错入场。
- 连续点击会取消或替换旧动画，最终数据状态不依赖 animationend/transitionend；旧任务不得覆盖新选择。
- 支持减少动态效果；键盘焦点、输入和点击不得因动画丢失或被遮住。
- 先使用现有样式和浏览器动画能力；仅在共享元素过渡确有需要时评估额外库，不为装饰引入重依赖。

### 4. 本机持久化缓存和加载

- 统一同月读取，合并重复计算；页面间共享原始快照和汇总，报告文件与采购证据按需读取。
- 内存缓存加本机持久化缓存；计算结果随输入数据版本和公式版本保存，下次启动检查有效后直接复用。
- 导入/替换台账、正式 ERP 成本变动、人工更正/撤销、仓储费率变动使相关缓存失效；代发和扣款更新报告相关结果。
- 工作区切换、备份恢复、计算规则升级正确更新缓存；限制内存和磁盘缓存容量，可重建，不影响原始账本与已定稿报告。
- 重计算在后台运行，避免锁住界面；状态区分已就绪、读取、重算、失败，过期值不能伪装成最新结果。
- 缓存键与月份对比范围一起设计，防止同时加载两个月时串店铺/串工作区/串日期。
- 兼容性迁移追加版本，在隔离数据验证；执行真实数据库迁移前另行明确备份、影响、回退及授权。本轮不执行迁移。

## 实施顺序与检查点

| 阶段 | 产出 | 进入下一阶段前的检查 |
| --- | --- | --- |
| A 范围与基线 | 检查现有分支/任务，补齐月份对比与最新动效预览，记录加载基准 | 最新交互一致，不能用早期被否定预览代替；确认单柱/明细左右位置 |
| B 数据基础 | 共享读取、版本失效、持久化缓存、后台计算及只读销售对比契约 | 精确金额、人工优先级、异常/空值和工作区隔离测试通过 |
| C 通用 UI | 统一表格、分页、筛选、弹窗、反馈、主题与动效基础 | 连续输入、分页定位、返回、减少动态效果验证通过 |
| D 页面整合 | 首页销售对比，利润/ERP、选品、导入报告和诊断逐页适配 | 窗口化、浅深色、长文本和完整操作路径可用 |
| E 候选验收 | 全量测试、构建、桌面验证、性能对比和 Windows 候选 | 所有本版必交项完成；无金额、持久化和交互阻断问题 |
| F 统一发布 | PR 集成、必需 CI、稳定版包、更新清单及资产回读 | 基线/标签/哈希匹配，稳定与 Beta 不串通道，按实际公开结果记录发布 |

## 验收证据

- 真实语义测试：同月/跨月、同店/缺店、28/29/30/31 天、未完月份、缺失日期、真实零、负值、微小成本、人工更正与撤销、定稿保护。
- 性能使用隔离的 1 万/10 万/30 万行数据；分开记录冷读取、首次计算、重启后的持久缓存命中、页间返回、切店、双月对比和数据变动后的重算，报告中位数与较慢样本及内存占用。
- 10 万行首次可用耗时较同机同数据基线明显下降；缓存命中下的常用切换以 300 ms 内为优化目标。目标需实测验证，不能用单个聚合步骤提速冒充完整页面提速。
- UI 检查 1440/1280/1024 宽、Windows 125%/150% 缩放、必要窄窗口、浅深色和减少动态效果；动效过程录屏/检查，不仅截静态图。
- 发布门禁：`pnpm --dir frontend test`、`pnpm --dir frontend build`，适用的 `pnpm --dir desktop verify`、桌面 smoke、实际候选用户路径和公开资产验证。

发布后如出现问题，优先回滚表现层或使可重建缓存失效；不直接把带新数据库结构的真实数据交给旧程序打开。降级及数据兼容性必须事先验证。

## 实施契约与文件边界

- 缓存负责 data、共享读取 hooks 和 worker；数据表仍为 v15，派生结果放可丢弃的独立缓存数据库。来源写入使版本失效；原始数据、定稿、导出继续执行原有验证，不以缓存替代正式证据。
- `readCachedReportProducts({snapshot, warehouseRate})` 返回异步精确商品行；界面根据当前快照接受结果，过期请求不能覆盖新选择。展示装饰不重复计算金额。
- 销售模块负责 SalesAnalytics、销售领域展示模型及独立样式；复用既有读取契约，月份对比不改变台账。
- 全局 UI 负责共享组件、布局、选品/导入/账本/诊断；主线负责利润/报告和最终集成。不同任务不同时写同一文件。
- 验收信号：连续数值输入焦点稳定、折叠表不预挂载、翻页只复位列表、缓存重启命中与修改失效、跨月/跨店准确、窗口化及减少动效可用。
