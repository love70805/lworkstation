# 私有源码与公开更新渠道分离

日期：2026-10-07。状态：**迁移进行中，尚未完成远端验收**。

用户已明确批准源码转私有，同时保留 `love70805/lworkstation` 原客户端更新地址。本批基线为 `d80076c`（v0.4.5 后主线），实施分支为 `codex/private-source-update-channel`；本文件记录迁移契约，不替代主线的远端操作与完成证据。

## 仓库职责

| 目标仓库 | 可保存内容 | 禁止流入的内容 |
| --- | --- | --- |
| 私有 `love70805/lworkstation-source` | 源码及开发历史、分支与开发标签、开发 PR、内部文档、测试、CI、构建和发布对应记录 | 凭据、真实业务库、业务 Excel、唯一备份等原有禁止提交内容 |
| 公开 `love70805/lworkstation` | 独立干净历史、必要下载/更新说明、版本 Release、安装包和配套分发资产 | 源码历史、开发分支/提交/标签、开发 PR、内部文档、测试、开发 CI、源码归档或源码包 |

公开仓库的版本标签必须指向自身的干净提交。私有源码版本与公开版本号、安装包哈希、更新元数据之间的对应关系记录在私有仓库，不通过推送开发标签或提交来关联。公开仓库自动生成的标签归档也必须只包含该仓库的干净说明内容。

未来开发 `origin` 指向私有源码仓库。迁移期间以及每次推送、PR 或发布前核对实际远端目标，不能把旧 remote 名称当作权限或仓库身份的保证。不得对公开分发仓库执行开发仓库的 `git push --mirror`、批量开发标签推送或开发分支推送。

## 发布与客户端更新

- 客户端 updater 的 owner/repo 继续为 `love70805/lworkstation`；现有公开下载和更新渠道保持，不切到私有源码仓库，也不向客户端加入 GitHub Token。
- 已有自动发布授权继续适用于通过验收的安装包、更新元数据、校验文件等分发产物和必要发布说明。源码、开发 PR、内部文档及 CI 均不属于公开发布范围。
- 开发 remote 改为私有 `origin` 后，`gh` 默认仓库推断随之变化。公开 Release 的创建、上传、查看、下载和回读命令必须显式指定 `--repo love70805/lworkstation`；开发 PR 和 CI 操作明确指向 `love70805/lworkstation-source`。
- 创建公开 Release 时使用公开仓库自身的干净提交及版本标签，不能将私有源码 SHA 作为公开 `--target`，也不能为创建 Release 而把开发标签推到公开仓库。
- 只有候选验收、正确仓库/通道核对、公开资产上传、匿名完整哈希校验以及生产更新入口回读通过，才记录发布完成。内部测试报告和源码对应证据保留在私有仓库。

例如，公开分发资产的只读核验应明确仓库：

```powershell
gh release view v0.4.5 --repo love70805/lworkstation
```

该示例仅说明目标选择，不表示本次迁移已通过公开回读。

## 迁移边界与待核验项

主线负责远端迁移并在完成后补写结果。当前以下项目均为待核验，不得因文档已经修改而标记完成：

1. 私有源码仓库可见性、完整开发基线及必要历史保全，开发 remote 和后续 PR/CI 目标正确。
2. 公开仓库仅保留独立干净历史与必要说明；公开分支、标签和 Release 关联不会重新暴露源码。不能仅凭默认分支文件变少就认定历史或引用清理完成。
3. 既有稳定/Beta Release 资产和更新元数据保全，原 owner/repo、下载地址、通道和哈希与迁移前核对一致。
4. 匿名读取公开资产、校验文件及生产更新入口成功；私有源码无法被匿名读取。
5. 根据实际结果记录完成时间、目标仓库、保全依据、公开资产核验及尚存限制。迁移前 PR/CI 链接继续作为私有文档中的历史证据，不保证旧公开地址仍可访问，也不据此重新公开开发内容。

迁移不创建空软件版本，不修改软件版本或客户端更新配置，不改写历史许可证或第三方声明，不自动安装，不清理或改写真实业务数据。历史已经授予的许可证和第三方声明不因仓库转私有而被文档重新定义。
