# 整体 UI 与加载优化规划

状态：2026-09-15 已随 0.2.16 交付并公开发布，详见 [验收记录](../RELEASE_0.2.16.md)。下方为规划依据，具体性能与边界以验收记录为准。

最新统一交付顺序、月份对比、动效与缓存验收见 [下一稳定版更新策略](NEXT_UI_PERFORMANCE_RELEASE_STRATEGY.md)。后续修正以该策略为准。

## 目标与范围

将工作区首页、选品、利润/成本核对、账本导入、报告和诊断页面放在同一套桌面交互规范下设计。优先解决重复入口、留白过大、明细无限展开、窗口化溢出、翻页定位和输入焦点；与本机持久化缓存及加载优化一起规划。

保留经营概览的职责，不把首页替换为利润面板；成本核对继续属于利润工作流，月度账本在首页有明确入口。沿用现有中文、蓝色主色、浅深色主题和模块化样式，不以改名或重排业务步骤代替体验改善。

## 已确认的每日销售方向

- 常规状态保留全月销售图表和销售额/销量切换，增加固定店铺颜色和简短图例；支持选择对比月份，共用刻度比较。
- 点击某一天后，图表缩成窄区，只保留当天的一根柱子；宽区用于当天商品明细。
- 当天柱子按店铺分段，段内显示店名和占比；悬停/聚焦显示金额与销量，删除下方重复店铺详情。不要用颜色代替文字。
- 返回全月恢复全月图表。分页回到明细第一行；从商品/活动详情返回则恢复原页码、搜索和滚动位置。
- 活动简写，不展开长原文，不继续撑长整个首页。
- 布局的左右方向尚未明确确认，需在下一次正确的预览中说明。之前“整块图表替换为表格”和“固定右侧明细抽屉”的预览不能视为最终获准设计。

待预览的交互细化：前一天/后一天、点击色段筛选店铺、窄窗口将图表压成简短汇总。不能把这些提案当成已确认业务要求。

图表数据验收：金额模式按销售额分段；切换销量时明确更换单位和占比口径。按店铺筛选后的占比分母需明确且稳定。负销售额、净额为零、缺失日期或缺失 SKC 需展示真实状态，不能直接套用全为正值的百分比柱；异常场景在实现前补充方案。切换日期比较柱高时使用一致刻度。

## 整体交互规范提案

| 元素 | 统一规则 |
| --- | --- |
| 页面顶部 | 标题、范围和主要操作形成清楚的层级，减少重复标题与入口。 |
| 月份/店铺 | 同一业务范围只放一组主要筛选；全月代发及独立扣款仍明确标注整月范围，不能被店铺筛选误导。 |
| 主次按钮 | 当前下一步突出，其余操作使用次级按钮或更多菜单；危险操作单独区分。 |
| 数据表 | 文字左对齐，数值右对齐，使用等宽数字；统一轻斑马纹、表头、选中态、空值和分页。 |
| 滚动 | 页面与表格各自负责清楚的区域，避免层层嵌套滚动。翻页重置目标列表位置，页面不跳动。 |
| 信息层级 | 列表先展示关键值和异常原因，详细来源按需查看；不能为简洁隐藏关键错误。 |
| 编辑 | 输入保持焦点，错误显示在字段附近；选择文件/来源、预览和保存保持明确状态。 |
| 弹窗 | 按内容分小型确认、普通编辑、复杂导入；标题与操作栏稳定可见，避免所有任务使用相同大弹窗。 |
| 返回 | 保留筛选、页码与滚动位置，并恢复到原触发控件；输入未保存时提供明确退出处理。 |
| 反馈 | 复制、读取、采集、回传、解析、采用和发布分别显示真实状态；失败说明原因和可执行操作。 |
| 动效 | 以轻量颜色/透明度/位移反馈为主，支持减少动态效果；主题切换避免全页重排和大面积模糊。 |

优先保证桌面窗口化可用。初始验证覆盖 1440、1280、1024 宽及 Windows 125%/150% 缩放；更窄布局按内容重排，关键操作和数字不能被挤出。中文字体采用本机已有字体，正文以清晰可读为准，不靠缩小字体解决密度问题。

店铺色只用于图表、图例和必要的身份标记；蓝色主操作、红色错误/扣款等语义保持独立，避免整行彩色影响阅读。

## 各页面优化提案

| 页面 | 优先调整 |
| --- | --- |
| 工作区首页 | 保留经营概览与月度账本入口；每日销售按上述最新交互重做；近期活动精简，占用可控。 |
| 选品工作台 | 搜索、筛选、导入/新增集中；档案优先商品信息，详细供应商/参考成本按需查看；修复窗口化按钮溢出。 |
| 利润核算 | 统一月份和店铺范围，利润汇总、待补成本、代发/扣款来源及报告操作层次清楚；移除重复流程说明和重复入口。 |
| ERP 成本核对 | 查询/复制与回传状态集中；异常可筛选；每项说明问题并直达人工更正或重试；采购证据不与整页明细连续展开。 |
| 月度账本/导入 | 批量文件呈现店铺、月份、行数和解析结果；无异常时一次确认；只展开需处理的冲突与映射。 |
| 报告与导出 | 未扣款报告和财务对账报告入口清楚；来源、已生成报告、历史修订分层；已确认的 Excel 模板不因软件 UI 改版改变。 |
| 系统诊断与备份 | 常用备份、恢复和通道状态突出，技术日志按需查看，错误可复制；状态与真实结果一致。 |
| 桌面外壳 | 应用导航、网页页签和当前业务位置清楚；版本弹窗按内容收紧；保持托盘、窗口和更新通道行为。 |

## 与性能方案衔接

- 同月台账共享读取，合并重复利润计算；列表和证据按需创建。
- 内存缓存用于当前运行快速切换；本机持久化缓存保存已完成的汇总和计算结果，重启后仍可复用。
- 缓存绑定工作区、账本、数据版本和计算规则版本；输入变化时使相关结果失效，防止迟到任务覆盖新结果。
- 繁重计算放到后台任务；界面保持响应，缓存过期时说明更新状态，不将旧值或未读取值当成最新结果/零值。
- 缓存可以重建，不能和原始台账、人工更正、已定稿报告或未同步业务修改混为一体。定稿和导出校验当前有效版本。
- 云端为未来方向：保留同步接口和版本设计，本轮规划不假定云端已存在，不上传真实业务数据。

## 实施及验收顺序

1. 统一设计规范，完成正确的首页交互预览；明确左右方向及异常金额展示。
2. 提供利润/成本核对和导入/来源编辑的代表性预览，验证同一规范能覆盖密集数据与编辑操作。
3. 按共享组件、首页、利润/ERP、导入报告、其他页面的顺序落地；各页面使用按职责划分的样式模块。
4. 将缓存、读取和计算优化与实际页面一起验收，分别记录冷启动、缓存命中、店铺切换、数据更新后的耗时与内存占用。
5. 验证所有页面的浅深色、窗口化、键盘、翻页、返回、输入焦点、长中文/SKC 和空/错误状态；核对精确金额、人工优先级、店铺隔离与定稿保护。

本轮交付是规划；后续实际软件实施完成后依已有授权统一测试、候选验收、GitHub 发布，本机不自动安装。兼容性迁移可在隔离数据编写和验证，真实数据库执行仍按项目规则取得明确授权。
