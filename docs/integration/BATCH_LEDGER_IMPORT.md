# 同月多店铺台账批量导入 contract 与任务包

状态：用户已批准功能范围；主线完成 contract 设计，待实现分工落实。本文不代表功能已经实现。

## 目标与基线

- 用户确认台账金额是销售原额；一次导入同一个月、不同店铺的多个台账文件。
- 基线：集成 `77b839f`，`main@0e0ad1c` 与其文件内容一致。工作分支 `codex/batch-ledger-import`，隔离目录 `.worktrees/batch-ledger-import/`。
- 现状：ImportPreview 只有单文件状态；Worker 已按 jobId 保存解析结果；saveSalesImport 单文件事务按同月 groupKey 替换旧行。循环调用现有入口会部分成功，也可能发生未预览的覆盖。
- 目标：整批预览、明确文件与店铺归属、处理重复和覆盖、整批原子写入，保留现有按店铺查看和月度合计。
- 非目标：跨月批量、同店铺拆分文件自动累加、多工作表批量、费用/退款新规则、ERP 成本规则、发布与安装包。

## 不变的业务规则

- CNY；销售原额与扣款分列，不将销售原额解释为结算净额，不增加隐含费用。
- 平台 SKU 仍是商品全局标识。同一 SKU 在不同店铺的销售行不得互相覆盖；ERP 成本仍按既有 SKU contract 关联。
- 已定稿/锁定月份禁止写入。人工与 1688 参考不得替代正式成本或改写历史利润。
- 按现有 groupKey（店铺、SKC、供方货号）替换，仅替换用户预览确认的重叠分组；不自动删除该店铺其他分组。

## 输入与预检 contract

新增批量入口建议为 previewSalesImports / saveSalesImports；saveSalesImport 兼容旧调用和返回结构。

批量输入：workspaceId、period、items。每项包含稳定 itemId、fileName、fileHash、storeName、mapping、filterOptions、经验证 rows 和 summary。批量期间 period 统一；变更月份、文件、店铺、映射或筛选必须使原预检与覆盖确认失效。

1. 一文件一店铺；文件名仅建议值，用户确认归属。店铺规范化沿用现有 NFKC/空白/大小写规则；批内同店铺阻断，不默认合并。
2. 映射店铺列时验证文件内店铺与确认店铺一致；不允许一个文件悄悄写入多店铺。缺少店铺列可使用用户确认值。映射模板只对兼容列头套用，不覆盖店铺确认。
3. 保留 CSV/TSV/XLSX/XLS 与单文件 50 MB 限制，沿用当前第一工作表行为并在界面明确。按文件排队解析，提供文件进度和整批进度，移除文件释放 Worker job。
4. 任一文件解析失败、错误行、无有效数据或必需映射缺失时，整批不可提交；用户可明确移除问题文件。主动筛选排除的行与错误行分开展示，不能用“忽略错误”静默丢数据。
5. 每文件预览：店铺、文件、有效/筛除/错误行数、数量、销售原额、扣款、新增分组数、替换分组数。总计采用现有 Decimal/截断口径。
6. 相同文件哈希先提示重复。仅工作区、月份、规范化店铺、文件哈希、有效映射/筛选条件均一致且对应数据未被后续导入替换时，才属于可跳过的已生效重复；相同字节被分配到不同店铺时阻断并要求核对，不能自动增加收入。
7. 已有重叠分组返回明确覆盖预览（店铺、分组、新旧行数/数量/销售原额/扣款），默认不覆盖。确认绑定预检结果，不能用一个永久布尔值认可之后发生的变化。
8. 预检生成可比较的目标数据状态签名。提交事务内重读账本状态和受影响导入/销售行；状态或覆盖范围变化时拒绝整批并提示刷新预览。

## 写入、重复与审计 contract

- 在一个 Dexie 事务内完成整批的重检、替换、importBatches、salesRows、ledgers 汇总和 auditEvents；禁止循环执行多个独立事务。
- 重复识别与写入必须在同一事务内重检，连续点击、提交后重试不能重复累计。全部为重复时返回无新增结果，不新增业务审计或改动账本状态。
- 成功结果包含 ledgerId、每文件 imported/skipped_duplicate 状态、batchId、新增/替换数量以及整批合计。文件失败时事务回滚，不能留下空账本、残留批次、删除后的旧数据或半批审计。
- 每文件保留来源哈希、映射、筛选、店铺、月份和现有销售行 batchId；沿用 imported 审计事件及现有同步 envelope。不新增权限动作、不修改数据库表结构；若实现必须改变持久 contract，先回主线审查。
- 每文件事件中的 ledger 快照使用整批最终汇总，确保按既有同步投影逐事件回放后的账本合计一致；现有替换语义及备份/恢复须有回归证据。
- 原子承诺针对本机写入；不新增跨设备分布式事务或在线协同锁。

## 页面与验收

页面顺序：多选/拖入 → 整批月份 → 文件清单逐项确认店铺/映射/筛选 → 统一校验与覆盖预览 → 确认整批导入 → 结果清单与月度利润入口。取消确认不写入数据；提交中阻止重复提交，错误明确落到文件。

必要用例：

- A/B 店铺同月导入，原始总量、金额、扣款与店铺/全月合计一致；相同平台 SKU 不串店。
- 完全重复文件、已生效重复导入、重复点击/重试不增收；不同筛选不误判为同次导入，旧文件已被更新替换时不误判已生效。
- 同店铺重复分配、映射店铺混杂、文件错误、缺少字段、零有效行明确阻断；移除文件后可重试。
- 重叠分组无确认不写入；确认仅覆盖预览范围；无关店铺与分组保持原样。
- 中途故障事务回滚；预检后数据变化与账本定稿拒绝提交，旧数据完整。
- 多文件记录可追溯；逐事件同步回放与备份恢复后最终汇总一致。
- CSV/TSV/XLSX/XLS、中文、前导零 SKU、同格式映射批量套用、筛选保留、桌面/移动布局；单文件旧流程继续通过。
- pnpm --dir frontend test、build、release:check、pnpm --dir desktop verify；真实浏览器多文件上传及按店铺利润查看。使用合成数据，不触碰业务文件或本机业务库。
