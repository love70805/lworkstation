# 0.4.36 正式利润表与导出命名

目标：商品成本、代发及各店扣款齐全后，直接预览、保存并下载正式利润表；已保存正式报告突出下载，扣款未齐时提供未扣款报告。导出名称为 `登记人2026年9月利润表.xlsx`，年月取账本月份，姓名取该报告冻结的代发来源。

基线：2026-10-17 实际联网核对远端 `main` 为 `adc2b331208eedeb465f13aa2e43584f889dd4dc`；源码版本 0.4.35，工作区干净。本批独立分支 `codex/monthly-formal-report`。

契约：内部沿用 `pre_deduction` 冻结基础与 `financial` 扣后报告。首次直接保存正式报告时在同一事务保存基础、正式报告、定稿状态和审计；失败不留下半成品。已有基础沿用冻结内容，后续扣款只能显式生成新报告，不覆盖历史。报告可追加冻结登记人姓名 `registrantNames`；旧报告下载从校验通过的冻结代发行推导。多登记人按源行顺序去重并列；手工总代发无姓名时仅用账本年月，不推测成员姓名。未扣款导出附 `（未扣款）`，正式导出无类型、修订号或“简化”后缀。文件名过滤 Windows 禁用字符。无数据库迁移。

影响：报告 repository、报告准备状态及展示、XLSX 文件名及月报区域样式；计算口径、商品与代发表布局、人工成本优先与真实数据库保持。

用户在实施中补充扣款导出求和不符与排序问题。原因是旧导出逐行截断金额至两位后写单元格，而总额先按源精度累加；扣款页没有实际店铺列，也没有排序。本批新模板 `profit-zebra@6-exact-deductions-by-store` 保留扣款数值原精度，仅以两位小数显示；逐行、店铺、整月及相关扣款单元格使用同一冻结值。明细按实际店铺自然顺序稳定排序，新增实际店铺列，不按供方货号猜店。已有报告下载校验正式报告自身及基础快照的哈希，从冻结扣款行重建扣款页、关联扣款值及排序，其余金额和原存档保持。缺失或损坏的冻结记录拒绝恢复，不猜测小数、不取当前新来源。

完成信号：首次直接正式保存、旧基础补扣款、扣款待齐、真实零、来源变化拒绝、锁定和重开保护、冻结姓名与旧报告兼容均验证；中文浅深色及窄屏操作通过；全量测试、构建、发布门禁、隐藏桌面候选验收、PR/主线 CI、稳定发布及资产元数据核对完成。本机不安装。
