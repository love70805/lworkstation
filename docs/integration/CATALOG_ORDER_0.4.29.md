# 0.4.29 属性顺序与多供应商保留

目标：修复描述文字与属性代码前后调换时的误报；正常保留多个供应商及同一供应商的商品页、店铺页链接，无需选择唯一来源或逐项确认。完成后直接公开稳定发布，本机不安装。

基线：2026-10-15 已通过 GitHub API 核对并 fetch 实际远端 main，提交 `52c98e3c7afecbf8a3c5a0bea3b674bbbb1950cd`，源码 0.4.28。执行分支 `codex/catalog-order-0.4.29`。

契约与影响：

- 属性比较新增明确的“描述文字 + 属性代码”双分支顺序等价；保留所有原文。代码、数量、颜色或描述内容不同，重复维度、数字区间、比例及无法确定的多段文字仍不合并，SKC 身份检查保持。
- 商品草稿与存储档案按已确认 ERP 供应商身份/链接唯一匹配补齐，合并全部链接和采购来源；未匹配的 ERP 供应商并列保留。人工内容与报价不被覆盖，不按名称强行合并不同身份的供应商。
- 供应商链接改为可直接打开的并列清单，取消采用单个来源按钮及“请选择”提示；已有全部链接可满足供应商来源资料完整性，无须填入一个唯一常用链接。
- 沿用现有 supplierProfiles、sourceLinks、sourceRecords、variants 字段与保存审计，将已有 ERP 的 stableSupplierId 一并保存在档案中，兼容旧 ID 格式；无表结构迁移。不改 ERP 正式成本、人工成本优先、月度定稿，也不改写真实数据库。

完成信号：真实案例的顺序差异不产生冲突或阻挡保存；不同内容仍保留核对证据；多个供应商及其链接、SKU、采购单关联保存重开不丢失，不新增报价或利润记录；中文浅深色及窄屏可用。完成必要回归、Windows 候选与包内验收、受保护 PR、CI、稳定发布和四资产公开回读。

验证：97 项定向测试通过；194 文件 / 1554 项完整前端测试、生产 build 和 17 组 desktop verify 通过。本机归档实际属性原文的只读复核已由不等修正为等价，原始记录未改写。24 组中文浅深色 × 375/768/1024/1440 页面布局及实际保存重开通过：两供应商五链接全部保留，常用链接可留空，无唯一来源选择或顺序确认；SKU 关联、报价、ERP 成本与利润记录一致，审计正常。真实属性代码变化仍显示原文差异。
