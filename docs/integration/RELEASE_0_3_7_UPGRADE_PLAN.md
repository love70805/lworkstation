## 3. 大台账性能

先在隔离环境复测上版五份文件，固定文件哈希、运行环境、冷热缓存条件及内存采样口径。对读取工作簿、校验、摘要、预览、写入、打开选品和档案分别计时，找到真正消耗所在。

代码核对发现`import.worker.js`同时构造格式化行与原值行，分块校验后仍累计完整校验结果；`getSelectionReferenceSnapshot`读取当前工作区全部销售行，多处建档/商品列表会取得这一快照。这些是待剖析的热点线索，不能仅凭静态阅读认定全部内存来源。

实施方向：

- 保留必要原始时间、金额、单号和源行，减少同一批明细的多份常驻副本，完成或移除文件后及时释放对应资源。
- 预览仅持有展示所需的小样本和摘要；校验/入库按块消费。若必须暂存大批数据，临时批次与正式数据隔离，失败可清理，完整校验与原子生效保持。
- 商品/档案按当前工作区、来源月份和商品身份读取；公共派生结果按来源版本复用。导入替换、ERP回传、人工编辑和切工作区时明确失效，不能用缓存展示旧成本。
- 每个阶段显示实际进度。取消先及时反馈，再完成后台终止或回滚，不能显示已取消但仍继续写入。

建议验收目标：同五文件、同采样口径下峰值内存较复测基线至少降低30%，总导入时间不退化；取消点击1秒内出现反馈，回滚完成另有明确结果。常见返回和重复打开目标1秒内可操作。上述是优化目标，尚未实测；交付报告列实际结果，不以减少读取行数、删源字段或跳过校验达标。

扩展容量测试使用合成数据覆盖10店、12个月及至少百万行累计来源，记录冷进入、切月、筛选、建档的耗时和内存；与五份真实文件验收分别报告。图表只有数千条模拟行时通过，不能据此宣称整年大台账已验收。

## 4. ERP任务恢复与现场闭环

用户日常流程：发起采集 → 查看简短阶段进度 → 成本完整后送达 → 工作台按原规则采用；可选图片等资料独立补充。现有自动回传与持久送达队列继续复用。

建议补充：

- 任务内分别显示“读取中、待继续、已送达、已采用/未采用原因”。扩展就绪只表示连接可用，不伪装采购已完成；商品资料未齐也不能把已生效成本退回缺失。
- 页面刷新或重开后，有可验证的本机任务检查点时提供“继续未完成采集”。只恢复原范围；账号、工作区、月份、请求、目标集或查询条件不一致则明确失效并重新查询。
- 已完整且仍可验证的目标复用；部分目标继续前复核分页/历史变化，无法证明一致则重读该目标。保留重复页、总数变化、超时、登录失效和取消保护。
- 检查点由扩展受控本机存储管理，记录必要标识、版本、完成目标与完整性；有限保留并自动清理。不存登录凭据，不把任务缓存写入GitHub或安装包。保留期限和空间上限通过实施时实测确定，不沿用页面缓存即永久有效的假设。
- 回传重试沿用稳定请求与证据身份；重复点击、重开和后台重投不能重复采用。未完成结果不作正式完整成本，人工更正与定稿保护仍先校验。

先核对真实ERP当前字段和分页，再执行受控只读采集，将验收结果接入隔离工作台。覆盖有销量/无销量的同SKC规格、共仓其他SKC、取消单、采购跨页、慢响应和掉线。真实业务库不作为验收写入目标；若未能完成现场路径，报告该项缺口并保留证据，不把隔离重放称为现场通过。

## 5. 连续建立商品档案

从参考页现有“未建档”筛选进入，使用当前全量筛选和排序形成临时处理队列，以SKC/稳定商品身份为单位，不只取当前页，也不取当前商品的每个SKU当独立档案。

编辑器增加“保存并下一个”，保留原有单个保存与返回。成功保存后才进入下一个；发生保存失败、身份冲突或保存期间新增未提交修改时留在当前档案，定位相关字段。下一条缺资料时允许按既定必填规则保存；名称和身份必须正确，可选图片、供应商或成本缺项仍不改变“已上架”的含义。

- 队列显示简短的“第N个/共M个”，已建档项即时更新；处理完返回原查询、排序、页码、焦点及滚动位置。
- 已被其他操作建档的目标重新核对，避免重复创建；切工作区或台账来源变化时重验相关身份和派生值。
- 跳过、返回或关闭时沿用未保存离开保护；没有修改不额外弹窗。普通保存沿用一次动作，不增加一层确认。
- 继续保护人工标题/图片/售价、主动清空和引流规格恢复选择。已排除的正常财务来源不被删除，资料晚到不覆盖编辑中内容。
- 缺项和来源沿用字段旁简短提示及折叠详情，优先补当前商品所需资料；原始采购比例仍只用于映射，不二次换成本。

## 6. 模块边界与实施顺序

| 顺序 | 边界 | 必须先明确的契约 |
| --- | --- | --- |
| A | 导入Worker、导入协调与profitRepository | 分块生命周期、取消回滚、正式生效、源行及原值追溯不变 |
| B | selectionRepository及资料派生 | 定向快照、来源版本、缓存失效、七天标签与最新售价结果不变 |
| C | ERP扩展后台/content、request与inbox | 本机检查点、账号/范围失效、完整性、幂等；不让资料请求改正式成本 |
| D | ProductLibrary、ProductEditor及模块样式 | 临时建档队列、保存成功推进、上下文恢复与编辑保护 |
| E | 隔离验收、候选与发布 | 同批范围统一通过后再交付 |

前两项性能剖析和ERP现场核验可以独立调查；实现时由一个版本执行对话协调文件所有权。新持久字段先改契约与兼容测试，DB迁移仅在必要时追加。a87e及主目录既有未提交文件保持，实施基于届时最新已发布main的独立工作区。

## 7. 验收与范围保持

| 场景 | 通过信号 |
| --- | --- |
| 五文件只读导入、重复、替换、取消、重开 | 源哈希不变，行数/数量/金额同基线；失败不留下半批；记录内存、耗时和响应 |
| 十店十二月累计、多次进入档案 | 全范围可查，来源切换无串店串月，缓存按实际变化失效 |
| ERP正常/中断/重开/跨账号/跨月/重复投递 | 恢复只复用有效证据，部分不冒充完整，人工与定稿不被覆盖 |
| 连续建档跨分页、跳过、已建档、保存失败 | 逐项一次保存、失败不跳走、无重复档案、返回上下文恢复 |
| 人工字段、引流恢复、未售规格 | 不覆盖人工，不反复加回排除项，不因无销量推断无成本 |
| 中文、浅深色、窗口化、键盘 | 短状态可理解，焦点稳定，主要动作可达，不靠悬停才能操作 |
| 现有财务与导出 | 正式成本/更正/定稿口径不变；导出两位截断、关联单号及代发/扣款规则不回退 |
| 干净安装包 | 无真实台账、派生业务明细、业务库、缓存或凭据 |

沿用纯本机Windows、既有销售与采购口径、四档历史七天标签和已确认图表外观。联网共用仍留待独立方案。实施已经获得用户批准，连续完成前端完整测试与构建、适用桌面verify/smoke、实际包内用户路径、PR/CI和公开资产回读；长期自动公开发布授权有效，本机安装仍不在范围内。
