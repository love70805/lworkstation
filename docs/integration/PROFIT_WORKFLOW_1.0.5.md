## 范围与契约

- 未录入代发也能预览、保存和导出报告：缺省代发数量按本次报告的零贡献处理，保留“未录入”来源状态，不伪造已采用的零值来源。已定稿报告继续使用冻结事实，不能默默补入后来数据。
- 代发支持明确录入店铺号，文件映射、人工录入、预览及导出保留归属；已有未分店的历史总量保持，不猜测归属。
- 利润与成本页共用单一搜索入口，移除利润页“本月销售趋势”，整理主操作和状态信息。中文浅深色和窄窗口验证。
- 导入货号筛选点击后直接采用；模糊搜索统一不区分大小写，保存原货号及 SKU 文本，不改变逐店范围与完整台账约束。
- 人工更正只输入非负成本并确认；界面不再强制填写说明。自动记录操作说明和审计，真实零值、微小值、当前工作区/月/店铺/SKU 限定、撤销和定稿保护保持。
- 错误显示具体阶段、原因和必要 ERP 返回数据；仅保留定位所需字段，过滤登录凭据及敏感传输配置，限制展示体积。新增传递字段先更新数据契约和测试。
- 单号调查覆盖 ERP 列表/明细、正式采用、人工更正与导出。截图已证明部分行是人工更正且采购证据不完整；此类行没有可引用的所选采购是空号的主要候选原因。核查并修复可复现的真实字段丢失，不编造或借用范围外采购单号；未取得现场返回时明确结论限制。

## 实现与审查结果

- 报告使用显式 `dispatchState=not_recorded`，零贡献、空来源列表与旧报告恢复兼容；直接生成正式版时对嵌套草稿保活，避免无代发分支提前提交事务。非负成本、人工优先和冻结基础继续回归。
- 手工代发按账本店铺录入，文件可映射“店铺号/店铺编号”或选择回退店铺；导出 E 列保存归属，G/H 原汇总位置保持。历史未分店总量不猜测。
- 单一查询同时匹配台账与当前采购证据字段；比较采用大小写兼容及全半角归一，原标识不变。导入匹配与勾选直接更新预览，重复同值不重新校验，真正导入仍由用户确认。
- 失败条目可带 `erpResponse` JSON 字符串，单条不超过 2,400 字符，只含有界业务返回，过滤凭据/请求配置；UI 最多展开 20 项。保留完整失败条目集合，诊断不参与成本资格判断。
- 采购列表有单号时沿用列表；缺号时只从同一订单明细补取，前导零与长文本不变。人工更正没有所选正式采购时不借用其他订单填号。
