# Shopeers 项目里程碑审计

审计日期：2026 年 8 月 7 日  
当前阶段：**本机真实数据 Beta 骨架（可供组内试用，尚未云端部署）**

## 业务边界

- 平台 SKU 是整个工作区的全局唯一通用标识。
- 平台 SKC 是 ERP 成本查询单位；一个 SKC 可返回多个平台 SKU 的采购成本。
- 默认币种为人民币（CNY）。
- ERP 成本是正式成本唯一优先来源。
- 1688 成本只用于选品参考；ERP 缺失时，必须逐账本、逐平台 SKU 人工确认后才可用于该账本定稿。
- 选品参考成本与月度精确利润严格分离。
- 月度账本定稿后不可被选品参考回流反向修改；定稿结果只能作为新的参考数据。

## 已完成

- 选品工作台、正式商品库、1688 采集待确认队列和商品编辑器已接入 Dexie 本地数据库。
- 采集记录支持手工登记、保存草稿、补齐平台 SKC/SKU/供应商报价、计算参考落地成本、确认入库或忽略。
- 供应商报价和 1688 参考落地成本使用统一公式；正式 ERP 成本不会被参考成本覆盖。
- 平台 SKU 在数据库索引和事务层均执行唯一约束，大小写和首尾空格不会绕过校验。
- 月度台账导入、平台 SKC 批量复制、ERP 成本批次发布、1688 兜底审批、精确利润核算和月度定稿链路已保留。
- 定稿结果可回流选品参考面板，但利润账本保持独立、可审计和不可逆修改。
- 工作区首页、顶部环境检查、通知、活动列表、支持摘要和数据量均来自真实本机数据。
- “数据安全与备份”已支持完整 JSON 导出、备份格式校验、平台 SKU 唯一性校验、恢复前回滚备份下载、恢复审计和真实清空本机数据。
- “系统诊断”已移除演示 API 延迟、扩展版本、端口和虚构错误，改为本机数据库、浏览器存储、备份状态和操作审计。
- 界面主要业务文案和无障碍名称已统一为简体中文。

## 验证证据

- Vitest：14 个测试文件、41 项测试通过。
- Vite 生产构建：1750 个模块转换成功。
- 内置浏览器 `http://127.0.0.1:5173` 桌面检查通过：工作区首页、数据安全、系统诊断均能读取既有 IndexedDB 数据，控制台无错误或警告。
- 已验证导出备份按钮会生成 JSON 下载并写入“已导出备份”审计记录；清空数据确认框在未输入确认文字时保持禁用。
- 已复核工作区数据库标识为 Dexie v5，导航和活动描述与当前领域动作一致。

## 尚未宣称完成的部分

- 当前仍是本机 IndexedDB，云端数据库、登录、成员权限、并发写入和跨设备同步尚未配置。
- ERP 与 1688 仍按既有手工复制/导入流程接入，尚未接入正式 API 或浏览器扩展自动化。
- 为保护现有用户数据，未在浏览器中执行会覆盖真实工作区的完整恢复/清空成功路径；格式和唯一性逻辑已有单元测试，危险操作只验证到确认门槛。
- 内置浏览器当前没有可用的 viewport 调整能力，因此 390×844、375px 和横屏需在具备移动视口的环境中补做最终视觉验收；现有响应式 CSS 已覆盖对应断点。

## 下一阶段开发路线

1. 先完成组内验收：用一份可复制的测试备份验证“恢复前下载回滚备份 → 恢复 → 审计回写”，并补移动视口验收。
2. 固化云端迁移方案：Supabase Postgres 表结构、工作区/成员权限、RLS、对象存储和审计不可篡改策略。
3. 在用户批准后创建 GitHub 仓库和协作分支，提交当前本机 Beta 基线。
4. 在用户批准后创建 Supabase 与 Vercel 环境，先部署只读预览，再迁移一份脱敏测试工作区。
5. 接入云端同步和冲突处理，保留本机备份作为导入导出和灾备通道。
6. 连接 ERP 成本抓取程序；继续以 SKC 查询、平台 SKU 归并、ERP 成本优先和逐项 1688 兜底审批为不可变业务规则。

云端资源、账号、数据迁移或上传动作在获得用户明确批准前，不执行、不创建、不上传。
