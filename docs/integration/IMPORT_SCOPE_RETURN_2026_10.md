# 导入筛选回归登记

日期：2026-10-07。状态：需求已登记，软件尚未实施。

用户已改变 v0.4.0 的范围方案：恢复导入时按店铺、负责供方货号筛选，再将选定数据导入；移除头像菜单中的运营范围筛选。保留 v0.3.13 已确认有效的 ERP 对象查询、采集检查点和正式成本修复，不以软件降级实现本轮数据清理。

当前优先事项是用户已授权的当前工作区业务数据清理。处理边界包括业务数据库及能回灌该工作区的 ERP/1688 请求、回传、断点和草稿。源 Excel、登录凭据与 Cookie、应用偏好、源代码、历史故障证据和独立备份不在删除范围。已有全库清空入口会同时清除设置，不适用于本次保留偏好的要求。

用户正常退出应用后，通过隔离副本中的 IndexedDB、Web Storage 和扩展 storage API 完成清理，写回后再次从实际存储创建副本并独立重读。业务表、相关回灌载荷归零，保留内容通过哈希校验；未启动真实 ERP 页面、操作可见界面、触发核算或重新安装。详细计数、处理脚本和校验记录保留在本机 `archive/data-clear-2026-10-07/`，不提交真实数据。

临时处理副本的递归删除被工具策略拒绝（`blocked by policy`），副本仍待删除；实际业务库清理已经完成，但整个清理任务的收尾尚未完成。不得将临时副本描述为已删除，也不将其作为永久业务备份留存。

后续软件实施应先核对原导入预览与筛选契约，在导入边界落实店铺、负责供方货号的范围选择，并验证入库结果、跨页面一致性和 ERP 目标契约。撤除头像范围功能时保留其他头像菜单功能与偏好，避免遗漏局部过滤造成“已导入但不可见”。继续遵守正式 ERP 成本优先、人工更正优先级、定稿保护、人民币与全局 SKU 唯一规则。

本次只登记需求与清理状态，不代表上述软件回归已经交付；不创建软件版本，不执行安装或 UI 演示。
