# 0.3.7 连续建档契约

基线：454b74f；批准范围见 RELEASE_0_3_7_UPGRADE_PLAN.md。

- 参考页“未建档”当前全量筛选结果按现有列表顺序组成临时队列，SKC 优先、缺 SKC 时以稳定 SKU 去重。只保存商品身份，不缓存草稿或财务明细；队列仅在当前页面进程存活。
- 路由携带队列标识和位置；逐项重新读取定向快照。已经建档的目标跳过；来源身份变化或工作区不一致拒绝写入，保留编辑内容供核对。
- 保存并下一个复用正式商品事务；只有提交成功且保存期间无新修改才推进。普通保存保持原行为；跳过/返回沿用未保存离开保护。每次写入传 expectedWorkspaceId，仓库在事务前及事务内验证工作区、成员及权限。
- 列表查询、筛选、全量顺序和分页由既有视图快照恢复；增加入口焦点恢复，滚动由真实 DataTable 容器恢复。下一商品将焦点放在名称字段。
- 人工字段、主动清空、引流恢复、可选资料晚到、财务来源默认已上架均沿用现有契约。不新增业务数据库版本，不改正式成本策略。

验收：跨分页、同 SKC 多 SKU、失败不推进、保存期间新修改保留、其他操作已建档跳过、来源变化和跨工作区阻断、跳过离开保护、返回页码/真实滚动/焦点；已有人工字段与会计预填回归；headless 浅深色窄窗口。

## 实施及验证

- ProductLibrary 使用按店铺隔离的紧凑参考读取，队列沿完整筛选后分组顺序创建；ProductEditor 根据当前 SKC/SKU 定向读取，没有身份时不启动全工作区读取。
- 保存前重新读取来源，事务传递 expectedWorkspaceId；其他操作已建档的未编辑目标自动跳过，正在编辑的目标保留输入并提示核对。来源移除、身份移动、工作区改变或页面重载导致临时队列失效均阻断队列写入。
- 保存自身触发的 liveQuery 回读在提交判断期间延后合并，避免把回读派生变化误判为新的编辑；真正保存期间输入的修改继续保留，第二次保存可更新同一商品后推进。
- 2026-10-02 定向回归 33 项通过：ProductEditor、ProductLibrary.recovery、continuousCatalogQueue。含 23 商品跨分页全量顺序、同 SKC 多 SKU 去重、冲突字段焦点、来源失效、跨工作区、其他操作已建档、保存期间输入和离开保护；既有标题/图片/售价/主动清空/引流恢复及晚到资料回归通过。
- Headless Edge 隔离合成库验收：23 商品队列从第 2 页启动仍始于全量第 1 项；键盘 Enter 启动，商品名称焦点可达；保存为已上架；完成后恢复第 2 页、查询、未建档筛选、入口焦点及实际窗口滚动 180px。1440/800/360/320 宽度的浅深色编辑器与参考页共 16 张截图，无文档横向溢出，已抽样人工审视。原入口因处理完所有目标而禁用时，焦点退回建档筛选。
- 23 商品合成场景两轮首档打开约 0.11–0.22 秒（最终一轮 216ms），仅代表此规模，不能替代百万行性能验收。脚本、完整测量、截图位于忽略目录 archive/release-0.3.7-continuous-catalog/。没有触及真实业务库或本机安装。

## 保存后的台账事实缓存契约

- 原慢路径：商品保存写入档案表后全局 revision 失效；下一条或返回参考页再次读取全工作区 salesRows。百万行场景该冷读曾约 45 秒。
- 保留全局 revision 对最终 `selection-reference@3` 的失效与读前/读后重核。新增 `selection-ledger-facts@3` 按工作区、台账及独立来源版本缓存只读事实；只有 products、platformSkus、supplierOffers、captures、auditEvents 这五张纯目录表写入不改变事实版本。其余任何表（包括未来新增表）、财务/ERP/台账、workspace/settings/member 变化均保守失效。实际 mutation 前及事务 complete/abort 后分别换版，不以条数或时间戳判断新旧。
- 事实保留 SKU/SKC 关系及冲突、旧 sku alias、未归属 SKU、真实代表来源与 sourceCount；先执行原坐标去重/冲突及完整月校验，再按月份聚合月末七日与其余有效日期，并单列无效日期/数量。售价按原最新业务时刻、退货净数量和零/微小价格规则计算；紧凑来源只留真实首条及计数，完整接口保留全证据。覆盖数量采用 80 位十进制，避免大数量抵消吞掉微小量。
- 每次最终投影仍读取当前商品、人工字段、供应商、人工成本、ERP 来源、财务历史、成员权限，重新决定身份归属、店铺、标题、价格、成本及利润。人工绑定后标签随当前关系变化；事实中不缓存目录归属、人工字段或正式成本决策，也不改原始财务明细。
- 单事实条目上限 16 MiB，事实内存和持久缓存各自总上限 64 MiB/24 条；最终普通缓存仍最多 8 条。容量估算展开 Map/Set，不能按空对象低估。超限或缓存不可用时回退来源计算。可重建 sidecar 追加 v2 元数据表，淘汰只读 key/bytes，不在保存后扫描全部事实值；业务库结构和备份不变。
- 首轮百万行实测发现原对象事实每台账约 6.12 MB，12个月超过总容量，尚未达标。因此改用无损字段元组去除重复字段名与继承的台账/月份信息；仅保留实际参与价格判定的日期候选副本，在 Worker 内恢复计算结构，主线程只解码可信身份。每个已有等价案例同时比较原始来源、普通事实及分台账编码事实。连续保存时删去同范围旧版本的最终投影，避免旧快照挤掉未改变的事实。
- 纯台账来源的队列校验使用仓库返回的可信 `referenceIdentities`，不依赖仅记录 ERP 附加资料的 `prefill.sources`，也不把用户输入的 draft 当作来源证明。原来源移除仍阻断；新增纯台账可保存、来源移除不可绕过回归。
- 2026-10-02 新旧定向回归 94 项通过（6 个测试文件）。含真实商品保存后推进/重启后目录再修改均不重读 salesRows、12 台账事实跨纯目录修改保留、同条数财务覆盖及导入替换失效、事务中先写目录后写财务再回滚、跨标签页版本变化、工作区读中切换、sidecar 不可用回退，以及冲突/缺失日期/跨店共同完整月份/人工归属的全量来源等价。100 SKU×28 天样本聚合后仅 200 条标签事实、100 条身份和100条封面数量事实，可信容量约 0.29 MB。百万行保存与返回性能由主线独立实测，不用小样本推定达标。
