# 大数据加载与成本确认响应（0.4.50）

状态：定位与隔离测量。2026-10-21 联网核对基线 `9c00019ba21df19d19bf45acc4941d062580debf`，稳定版 0.4.49。目标是降低数据增长后的页面加载、证据查看和确认/人工更正卡顿。

- 保持成本优先、商品档案按需补齐；本地页面读取与核算另行分析，不把 ERP 采集排程当作全部性能问题的原因。
- 只优化当前账本范围、展示证据的读取时机、重复扫描和同一事务内重复读取；不删证据，不绕过保存前核验，不改变人工优先、CNY、零值/微小值、撤销、工作区隔离和定稿保护。
- 用相同合成大数据做前后对照，记录页面/操作耗时、主线程阻塞和数据库读取次数；合成结果不能代替真实账号的完整性能承诺。
- 无业务库迁移，不改写真实业务库、收件或检查点。完成信号为针对性回归、完整候选门禁、实际用户路径及稳定交付。

## 实施与隔离对照

复用利润页账本快照，收件/请求按账本读取；列表只投影持久化状态，打开详情才核验对应回传；人工更正按工作区/账本/店铺/SKU 建立本次计算索引；更正事务复用已读取的销售行和 ERP 成本；历史补查只查询目标 SKU 的可靠关联，没有关联时不加载采购证据。所有正式写入仍走原始证据校验与仓库事务。

同一 headless Edge 环境、12,000 条销售明细、1,500 SKU、500 条人工更正、30 个当前待恢复回传和 30 个异域回传。安装包复核前的两次生产构建测量：首屏 19.25 秒降至 1.36–1.54 秒；打开更正 4.55 秒降至 0.62–0.75 秒；页面保存 4.84 秒降至 1.00–2.08 秒；确认真实价格事务 1.56 秒降至 0.44–0.47 秒。该场景含启动回传恢复积压，读数带数据库/长任务观测开销，不能作为所有真实账号的耗时保证。
