# 0.4.52 轮询响应内存释放

修复成本核对页长时间停留时，已完成轮询的取消监听保留旧响应并持续累积内存的问题。请求成功、失败或取消后立即解除监听；预先取消的请求不再启动传输，并保留并发请求独立完成、取消与延迟失败语义。正常轮询频率、业务数据和财务规则保持，无业务库迁移。

## 复现与验证

0.4.50 与 0.4.51 的原收件传输文件 blob 相同（`da93ad69ba0d9caaea41f8ff039b197151aa4e1b`）。用户确认尚未升级；本轮先用隔离合成响应验证泄漏，再以 0.4.51 和 0.4.52 实际安装包补充验证。

| 验证项 | 旧实现 | 0.4.52 |
| --- | ---: | ---: |
| 同一取消信号完成 1,000 次请求后，残留监听 | 1,000 | 0 |
| 上述隔离传输测试回收后的堆内存 | 3.93 → 67.28 MiB | 3.93 → 4.11 MiB |
| 原生页面约 1,000 次加速请求后的存活监听总数 | 1,030 | 10 |
| 原生页面正常轮询 3 分钟的存活监听总数 | 12 → 72 | 10 → 10 |

第一组测试用 Node 24、每次新建 8,192 个数值组成的合成响应，以强制垃圾回收区分活对象与短期分配；约 4 MiB 不代表整个软件内存。原生页统计包含路由等基础取消监听，故修复后为 10 而非 0；观察器仅使用 WeakMap/WeakRef，不额外持有响应或监听回调。

原生隔离数据为 12,000 条销售、1,500 SKU、500 条既有人工记录和 60 个回传。加速阶段仅将任务轮询间隔 3 秒缩短至 30 毫秒，以重复同一生产路径；随后卸载并恢复正常轮询 180 秒，观察六个时间点。新版正常阶段未强制回收的页面堆约 54.1–57.4 MiB，阶段首尾回收后为 53.24 → 53.48 MiB；六轮更正与切页后约 79.32 MiB，基础监听仍为 10。不同页面会装载缓存和数据，本结果不声称整机内存恒定或证明数小时真实 ERP 采集无其他增长。

旧版第一次加速净增断言受到初始化 effect 退出影响而误报；原始日志保留，修正为检查末态存活监听后，只重跑加速复现确认。原生正常频率观察未重跑或改写，详细说明在忽略归档。

215 个文件 / 1,724 项本机完整前端回归通过；共享传输和收件路径定向 3 文件 / 26 项通过。生产构建、CI 全部 30 项发布门禁及 19 组桌面检查通过。最终安装包 764 个安装文件、719 个生产输入和 667 个前端文件逐字节一致；隐藏启动、内置助手 8.0.48、更新状态 current、原生确认采购价、人工微小值更正、审计和 60 个回传记录核对通过。最终原生包连续观察及六轮更正/切页通过，可见窗口 0。
