# 2.0.7-beta.4 界面与运行响应

基于已发布 Beta3 和远端主线 `1c9922060a45bce39382564eb8bbae62580d9e64`。业务基线继续为 v2.0.6，保留独立 Beta 安装、工作区与 `beta-sidecar` 更新通道。用户要求继续优化界面并兼顾运行流畅；目标办公配置为 i5-11400、16GB 内存、无独立显卡，未在该实机执行验收。

## 本批改动

- 报告来源检查只读取目标报告，复用来源版本缓存；大台账分批读取、分批传给既有后台线程，后台生成来源指纹。历史指纹格式及文件保持原样，当前来源改变会失效并重算。
- 搜索延后结果更新以保留输入响应；按不变的数据行复用分组，金额仍用高精度十进制累计，最后才按原有规则展示。店铺缺成本计数不再重复进行整份金额汇总。
- 利润页合并明细开关与分组工具栏，压缩报告、成本说明的重复行。保留整月导出和当前明细筛选的范围区别，以及缺成本待办。
- 导入页合并重复统计，核对已选货号复用分页清单；移除即使折叠也会生成全部勾选项的重复清单。选择、应用校验和导入仍为独立明确的状态。
- 月份和店铺选择继续使用现有 BoardUI / React Aria；补齐长选项断行和仓储卡片的内部键盘焦点描边。没有新增依赖或持续动画。

边界：不改取价、费用与补充来源业务口径，不迁移真实库、不改写历史报告、不执行本机安装。已登记的跨模式取价及来源共享等业务差异仍见[任务看板](../CODEX_TASK_BOARD.md#软件实现与项目约束的差异)。无账本时的 ERP 成本文案已随实际流程修正。

## 界面与实际流程

沿用中性底色、蓝色操作和语义状态色，字体保持 Inter / Microsoft YaHei 与现有数字字体。阅读顺序为月份/店铺、整月报告、成本待办、商品小计与筛选、明细。相关工具按 4px 刻度紧凑排列，导出、成本与明细之间保留明确分组。

- 14 组截图覆盖 1440×900、1024×768、1024×576、浅深色、导入三种状态、报告当前/已变化及长店铺名；没有整页横向溢出或字体加载错误。同一合成账本在 1024×768 的首个分组位置从约 y=749 前移到 y=680，保持原有数据字号。
- 菜单方向键、Esc 返回、React Aria 月份/店铺选择、明细 Space/Enter 开关、焦点保留和折叠时卸载表格通过。仓储按钮焦点为 2px 内描边，避免摘要容器裁剪。长英文店铺选项可换行。
- 720×450 CSS 视口验证相当于 1440×900 窗口放大 200% 后的布局空间；页头换行、操作和明细开关可用，数据表在自身容器滚动。这是等效视口检查，未替代 Windows 显示缩放实测。
- 完成小文件选择、应用校验、导入、成本补齐、Excel 下载、来源改变提示。明细仅选一家店时，报告仍覆盖整月全部店铺，其他店铺缺成本提示保留。
- 完成 20,000 行 / 1,000 SKU / 334 货号合成 CSV 全流程：解析预览约 1.35 秒，选择 334 货号约 85ms，校验约 1.27 秒，写入约 3.03 秒。选中后只挂载 22 个勾选控件；写入后核实为 20,000 行和 1,000 SKU。正常 CPU，单次功能验收数字。
- 另用 20,000 行 / 27 SKU 的完整利润页面验证同时读取利润和报告来源、连续搜索、人工成本更正后的报告状态失效；浏览器无未捕获错误。
- 最终布局检测覆盖相关 CSS 和 JSX，返回 `[]`，没有未解释项；以实际截图与键盘结果补足机械扫描不能证明的阅读顺序、容器及焦点行为。

## 性能对照及限制

同机 Edge headless、Vite 开发模块、4 倍 CPU 降速、隔离合成数据。来源检查使用 27 SKU、12 份报告，每组 3 次；搜索预热索引后匹配全部 SKU。表中不是整页渲染、完整 Electron 内存或真实 ERP 耗时。

| 场景 | Beta3 | Beta4 |
| --- | --- | --- |
| 2 万行来源检查，报告不带文件载荷 | 2.71–2.96 秒；最长主线程任务 1.56–1.78 秒 | 冷检查 2.17–2.48 秒；未观测到超过 50ms 的主线程任务 |
| 2 万行来源检查，每份报告带 1MiB 载荷 | 3.02–3.83 秒；最长主线程任务 1.75–2.38 秒 | 冷检查 2.43–2.66 秒；未观测到超过 50ms 的主线程任务 |
| 2 万行、来源不变的重复检查 | 每次重复完整读取和散列 | 7.0–11.1ms |
| 1 万 SKU 搜索、分组和汇总 | 428–461ms | 初次分组约 359ms；可复用分组时 133–139ms |

分批操作主要降低主线程连续占用，首次处理仍需要完成必要读取和计算。CDP 降速不保证后台线程同等降速，也不能模拟指定 CPU、16GB 系统内存或集成显卡；没有据此承诺整机帧率和内存上限。新后台线程复用既有池与空闲回收，来源缓存继续受现有容量预算限制。

可复核材料保留在本机 `archive/ui-beta4-20261109/`，包括基准原始记录、截图、完整导入和大台账页面结果。Beta3 对照在 `archive/ui-next-review-20261109/`。
