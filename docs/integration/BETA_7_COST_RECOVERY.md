# Beta.7 · ERP 成本回传恢复契约

范围：修复 Beta.6 中「可预览 ERP 候选价，但正式成本仍缺失」的可复现路径。现场截图只证明三笔采购可算出 4.59 元候选价，未包含收件、请求与采用状态，不能单凭截图确定现场阻断原因。

## 契约与影响

- Beta.5 创建的旧请求可能记录查询 SKC，却没有 `expectedSkus`。自动收件仅从同工作区、同账本、请求时间之前已导入的销售行重建平台 SKU 范围；同一 SKU 的 SKC 归属不唯一、请求时间或范围缺失时阻断。请求之后添加的 SKU 保持查询辅助证据，不能扩大旧请求的正式成本范围。事务内的正式发布再次重建并验证范围。
- 旧版成本页保存的完整 v2 JSON 草稿，在工作区、账本、请求均匹配时，使用稳定投递 ID 进入持久化收件箱，再由原自动采用流程处理。旧 TSV / v1 只供人工核对；草稿中已有收件关联或异常更正时不迁移。重复扫描不应重复发布，持久化收件后才删除草稿。
- 撤回的较新回传保留墓碑语义：正式成本保持缺失，不能让更早成本或旧收件重新生效；需新的可信回传或显式人工更正。
- 成本详情从当前账本实时成本行重算，明确区分候选价与已采用成本，展示收件阻断原因；自动收件不提供手动采用按钮。人工有效值优先，定稿/锁定账本仍禁止写入。

## 验收信号

- 旧请求和三笔采购（20×4.5、15×4.5、15×4.8）在归属完整时采用 4.5900 元；请求后的 SKU、重复投递、异工作区草稿不扩大范围或重复发布。
- 人工零值更正及撤销回退、定稿保护、撤回批次后的成本回退保持原口径。
- 前端针对性及完整回归、生产构建、桌面验证与候选隔离业务路径通过后才发布 Beta.7；不改真实数据库，不在本机安装。
