# 0.4.53 成本确认与利润界面响应

修复已采用正式成本较多时的采购历史重复排序，将账本覆盖率和已有成本列表重计算移入独立计算线程；利润只随财务来源变化刷新，避免回传状态或审计更新反复重读整月证据。后台单轮临时共享超出常驻缓存上限的账本输入，切页取消旧列表计算并保留分页；没有实际资料执行的旧任务不再显示“正在准备后台补充商品资料”。

## 复现与测量

相同浏览器、同一份已完成初始恢复的隔离数据，包含 12,000 销售行、1,500 SKU、500 条人工记录、900 条正式 ERP 成本（每条 120 笔采购历史）及 60 个回传。先运行基线源码的只读计算，再运行候选源码；金额及匹配结果一致。以下是各函数自身耗时，不是整页秒开承诺。

| 读取或计算 | 基线 0.4.52 | 0.4.53 |
| --- | ---: | ---: |
| 账本快照（含数据库与覆盖率） | 5.45 秒 | 2.24 秒 |
| 成本列表 reconciliation | 9.47 秒 | 1.44 秒 |
| 单独覆盖率计算 | 4.69 秒 | 0.69 秒 |

最终包资源的 headless 冷进入利润明细约 5.44 秒、成本页约 7.61 秒，包含模块、数据、Worker 和界面准备；确认采购价保存约 3.36 秒，随后 12 秒观察窗最大单次主线程长任务约 0.75 秒。原生页面确认保存约 3.82 秒（含跨进程触发与轮询等待），最终 ERP 成本 3 元、人工微小值 0.00002 元和审计正确。这些单次读数不证明所有设备都相同，也不宣称大账本没有加载等待或所有短卡顿均已消失。
