## 交付目标与顺序

按 A → B → C → D → E 实施，整批验收后统一发布 Beta.6。优先保证成本正确生效，再完成展示与入口精简。

### A. 正常 ERP 成本自动采用（最高优先级）

- 回传接收后，由业务服务统一校验工作区、请求、账本月份、SKU 归属、批次完整性及采购证据；数据层独立复算，通过的正常项自动写入正式成本。不得依赖用户打开成本页或点击采用按钮。
- 批次级归属/封装校验失败时整批不写入；可信批次中的单项异常只影响该项。区分批次不可信与 SKU 证据不合格，不因放开部分成功而省略校验。
- 合格成本按该账本月份取当月及以前最近三笔采购，数量加权、四位截断；利润精确累计后再截断，1688 仍只作参考。
- 人工更正在当前工作区、月份、店铺和 SKU 范围保持最高优先级。后台合格 ERP 证据可保留，不能覆盖人工有效值；撤销更正后恢复最新可用 ERP 成本或缺失状态。
- 已定稿/锁定账本不自动改变；新回传保留证据并说明保护原因。写入事务内再次校验锁定、归属和人工状态，防止并发变化。

先形成并测试跨模块契约，再改实现：

| 契约 | 设计要求 / 验收信号 |
| --- | --- |
| 部分成功 | 分别保存已采用项、剩余异常、缺失项及保护原因；存在剩余项时不把整批标为全部完成 |
| 幂等 | 以可信源批次、账本、SKU 及证据/处置版本识别处理；重复投递、重复触发和重启不重复记账或制造重复成功审计 |
| 重试 | 已成功项保持稳定；异常修复后只重新处理受影响项；事务失败可恢复，不吞掉未处理证据 |
| 新旧回传 | 明确同 SKU 多批次排序与过期请求处理，迟到旧批次不能把新成本回退 |
| 审计 | 记录源请求/批次、采用方式、证据、前后值、处理结果及失败原因；自动操作有明确系统来源 |
| 恢复与撤回 | 兼容旧 pending/loaded/applied 记录、草稿恢复、历史查看和原有撤回入口；部分采用不能丢失关联历史 |

影响：`erpAdoptionReadiness`、批次/inbox contract、`profitRepository`、接收调度和成本页。先评估现有表能否容纳状态；如需表结构变化，追加数据库版本，记录备份/恢复兼容性，隔离测试，不在本轮规划执行真实数据迁移。

验收：正常与异常混合批次中正常项直接生效；重复投递、并发、重启重试无重复写入；异常解除后补齐；跨月/跨工作区/无归属/不完整批次拒绝写入；人工和定稿保护均通过。用户截图中候选 4.59 元的计算已确认，实际批次未采用原因仍未读取验证，不预设现场根因。

### B. 成本状态与属性展示

- 成本核对显示“当前有效成本”和“本次回传处理状态”，区分已生效、校验/采用中、证据不完整、采购异常、未取得成本、人工有效和定稿保护；失败说明下一步，不能统一提示缺少成本。
- 概览显示自动采用数量和剩余待处理数量；筛选仅改变展示，不改变后台采用范围。人工操作集中于异常处置，并保留主动更正能力。
- 从已有账本销售明细补齐 SKU 属性，使表格、搜索和详情一致；同 SKU 多种属性描述保留来源，匹配仍以平台 SKU 为准。
- 不要求用户重填属性或重导入；缺失成本不能因为内部零占位而显示为真实零成本。

验收：已有账本直接显示属性；冲突描述可追溯；正常成本无需人工点击；状态与实际持久化结果一致，异常提示可被键盘和辅助技术感知。

### C. 导入月份自动识别

- 新建账本依据台账有效日期识别月份，明确单月自动填入；解析结果携带识别来源、月份分布及缺失/无效日期信息。
- 混月、无可靠日期、多文件月份冲突时展示原因并要求明确选择，不用系统时间、活动日期或采购日期代替台账日期，不新增自动拆分多账本功能。
- 已有账本月份权威，来源不一致明确提示；用户主动选择后，后续异步文件解析不能静默覆盖。增删文件、修改字段映射或筛选后重新检查建议和冲突。
- 保留当前整批预览、重复/覆盖确认和已定稿保护；修改月份后原预览失效，重新校验。

影响：导入解析/Worker contract、`ImportPreview` 及对应测试。验收覆盖历史单月、混月、日期缺失/无效、多文件冲突、删除文件、异步乱序、人工选月和已有账本冲突；用户原表仅只读核验，不复制入仓库。

### D. 利润、成本、导入界面优化

- 删除旧重复入口栏，将唯一主标题、月份、店铺放在同一区域；“利润明细 / 成本核对”相邻，两个视图都能切月份。
- 普通成本导航归并到页签；异常直达入口保留。新报告保留一个明确入口，预览、保存和下载集中在报告区域。
- 保留旧账本原格式导出、历史报告原文件下载和整月状态；不能把当前店铺筛选误当整月定稿范围。
- 合并重复说明，长说明折叠；保留读取中、失败和异常反馈。月份/店铺/视图共用现有状态，往返保持筛选、展开和位置。
- 建议附带将侧栏“系统与备份”改为“系统检查”，备份仍在页内可达；沿用原设计与轻量动效。
- 同步整理三处连续操作的视觉层级：利润页突出月份、店铺、关键结果及下一步；成本页先显示自动生效结果，再把异常按原因和处理动作分组；导入页把识别月份、文件冲突和整批预览放在同一阅读顺序。每种状态只保留一个主要动作。
- 状态文字必须与数据状态一致：正常采用有完成反馈，异常卡片显示原因及可执行动作，处理中可见进度，失败可重试；不要用颜色作为唯一提示。保持页面现有字体、色板、间距和组件体系，不扩展为全站换肤。
- 窄窗口允许控件换行，主要操作仍可见；表格保留横向查看能力但页面主体不能横向溢出。表单标签、键盘焦点、错误播报、浅深色对比及减少动态效果一并核验。

验收：对同一组隔离数据保留改前/改后截图；检查 1024/1280/1440 宽度、浅深色、缩放、键盘焦点与减少动态效果；月份连续切换不显示错月结果，窄窗口不截断主要操作。覆盖空账本、正常成本、部分成功、异常、人工覆盖、已定稿、读取失败和旧报告状态。首页图表与已确认报告格式不重做。

### E. 回归、候选与交付

1. 先完成契约/数据层定向测试，覆盖 A–C 的业务边界，再做页面路径验收。
2. 发布前完成前端全量测试、生产构建、适用桌面 verify/smoke，以及隔离数据的“历史台账导入 → ERP 回传 → 部分自动采用 → 异常处理 → 利润核对 → 报告”完整路径。
3. 用户已允许本次前台测试。业务回归仍优先后台运行，随后集中一次前台验收真实 Windows 窗口中的页面布局、浅深色、缩放、键盘交互、返回位置与必要的窗口行为；不反复启动或抢焦点。同一候选已通过的场景不重复演示。
4. 获准实施并完成后，通过必要 PR/CI 集成、候选验收、Beta 发布及公开资产/哈希/更新通道回读；稳定通道保持 0.2.19，本机暂不安装。候选与证据按项目规定归档。

本规划文档阶段仅检查差异和链接，不运行软件测试、不修改版本号、不创建软件版本。大规模缓存改造、云端工作、首页重做和真实数据库批量改写不在本版范围。
