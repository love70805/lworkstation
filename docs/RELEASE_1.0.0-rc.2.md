# 1.0.0-rc.2：全部成本核算后统一整理商品资料

状态：已公开候选预发布（非草稿）。[下载与更新](https://github.com/love70805/lworkstation/releases/tag/v1.0.0-rc.2)；稳定 Latest 保持 0.4.54。

此前每批成本回传会立即被商品页使用并触发自动建档。新助手 8.0.50 的新任务改为：采集全部成本 → 等待本机逐批核算回执 → 统一复用暂存资料补全商品与自动建档。必要的目标身份和平台 SKU 映射仍用于成本范围校验，阶段文字明确显示用途。

目录、映射、图片、供应商和完整采购证据随成本收件暂存。资料阶段按同一任务、批次和尝试恢复持久种子，已完成目录、映射与采购历史不重复请求 ERP；只补缺失来源。旧尝试、其他工作区、范围变化和未完成核算均拒绝提前放行。暂停、中断和重启保留已送达成本，继续原任务复用暂存资料。

只有资料完整且满足既有校验的预存商品才自动进入选品库，缺失图片、来源链接或属性的资料继续保留待补。新助手继续旧任务也采用新顺序，已送达成本不重采；不会回删已存在商品。旧助手继续兼容原任务协议。人工有效成本、真实零值、微小正值、CNY、平台 SKU 唯一约束和定稿保护保持，不执行真实业务库迁移或删除。

隔离证据：10 个目标分两批，共 40 次 ERP 请求；最后一批核算回执前无资料整理，之后完成两批资料整理未增加 ERP 请求。真实 HTTP 收件、扩展后台与页面联合验证了持久资料复用；自动建档组件验证最后一批回执后仅流转一次。

等待本机核算时遇到收件服务重启，会保留已送达成本并等待继续，不提前整理资料或将断线误报为 ERP 读取失败。发布审计发现测试依赖的两项已公布问题后，Vitest 升级至 4.1.12，保留 low 级审计门槛；参见官方 [手动 mock 修复](https://github.com/vitest-dev/vitest/security/advisories/GHSA-qxg6-89mg-rqv8)和 [Windows 路径修复](https://github.com/vitest-dev/vitest/security/advisories/GHSA-xp26-3454-mjgp)。

Windows 远端审计同时发现 Electron 44.2.0 的已公布权限来源归属问题，桌面运行时升级至同一 44.x 系列的 44.3.0，并重新验证原生扩展和最终安装包。见 [Electron 官方说明](https://github.com/electron/electron/security/advisories/GHSA-fw47-9c62-h3vw)。

全新冻结依赖下 218 个文件 / 1,738 项完整前端测试、生产构建、31 项发布门禁和 19 组桌面检查通过。最终包 239 个程序文件、194 个生产输入和 142 个前端文件逐字节一致；包内 Electron 44.3.0、助手 8.0.50、隐藏启动、RC 更新及原生启动/刷新/断线恢复通过。16 组中文浅深色 × 980/1440 布局检查无溢出，可见窗口 0。
