## 契约与范围

- 使用增量 SHA-256 消费与既有规范序列化完全相同的字节；预览令牌只保留摘要，历史来源与报告完整性摘要保持可比。对象键顺序、数组顺序、旧来源状态的排序、Unicode 和特殊字符均以旧算法为准。
- 直接导出只准备一份计算快照；写入事务内重新核对来源内容、工作区、权限和报告修订，仍拒绝同条数来源修改和过期保存。预览后保存的旧接口继续要求有效令牌；不以可丢弃缓存或行数替代正式来源校验。
- 来源快照在生成必要报告行和摘要后释放，报告列表和任务状态通过游标或小批量读取丢弃大载荷，避免 `toArray()` 后才去掉文件或采购证据。
- 新报告生成时完成最终下载格式；旧模板继续只读兼容。金额、数量、长编号、代发来源顺序、合并和历史快照均保留，不通过删行或裁剪原始证据节省内存。
- 同步检查新导出、预览保存、来源变化提示、阶段进度、失败重试和历史下载。仅合并重复派生读取，不停止 ERP 采集或忽略并发数据变动。

## 验收与完成信号

摘要对照覆盖旧字节表示、大字符串边界、Unicode、源记录同条数修改和核算上下文。报告回归覆盖人工零及微小正数、成本变化、权限变化、事务失败和旧快照下载。隔离大数据完成两种上下文、连续导出及重开下载，测量每阶段内存和结果一致性；修复后再完成必要构建、桌面候选、受保护 CI 与同一 Beta 通道交付。

现场日志、路径、详细实验和候选材料留在忽略归档。原型只验证了规范序列化与摘要热点，不能作为完整 Electron 导出的性能结果。

## Beta.16 实现与验证

- 规范序列化使用固定版本 `@noble/hashes` 的增量 SHA-256，保留旧摘要字节表示。预览、生成、保存与历史完整性检查共用有界编码；读取阶段的计算可以让出主线程，最终写入事务内同步分块复核，避免原生 IndexedDB 提前结束事务。
- 新的直接导出接口只构建一次报告结果，写前仍从数据库核对完整内容、当前权限、核算上下文、任务和采用状态。预览后保存接口保持过期令牌校验。报告草稿不再保留完整台账和全部采购证据。
- 报告头和编辑保护逐条提取必要字段。文件处理期间暂缓报告来源状态的重复派生读取，完成后重新核对。
- 新报告保存明确的最终文件标记，首次和历史普通下载校验后直接返回该文件；旧报告与“补齐代发单号”继续使用原兼容转换。Base64 逐块解码，避免逐字符构建中间元素列表。新旧路径的金额、文本编号、字体、对齐、边框、列宽、行高和合并已作对照。

完整前端回归曾通过 254 文件 / 2,087 项；随后原生事务适配和新增边界用例的相关 51 项通过，最终强制 CI 另行记录。桌面 verify 通过。隔离原生浏览器使用生产方式编译的模块与合成数据库，覆盖 60,000 条台账、877 SKU、105,240 条采购记录：常规连续三次、最低模式一次及重开后的四份历史下载通过，数量、收入、成本、利润和历史文件校验一致。

该同机样本的渲染进程峰值工作集从 Beta.15 的 2,420.5 MiB 降为 662.2 MiB，约降低 72.6%。常规导出从约 10.0–10.2 秒变为 11.2–11.4 秒，最低模式从约 8.5 秒变为 7.8 秒；改善主要是内存峰值，不宣称普遍提速。测试为隔离浏览器导出链路，未使用真实业务库，不等同于已在用户完整桌面环境复现原崩溃。最终安装包仍需独立隐藏验收和通道核对。
