# 下一版计划：0.3.0-beta.6 · 利润页面精简与导入核对

日期：2026-09-22。基线：已发布 Beta.5，当前主线 `b5d09d4`。

状态：待审阅的版本规划。本轮只写计划，未修改业务代码、版本号或发布软件。继续纯本机 Windows Beta 线，本机暂不安装的约定有效。

## 目标

让用户进入利润页后，直接看到核算月份、店铺、利润明细和成本核对；减少重复标题、导航、说明和按钮，把首屏空间留给核算数据。

## 已核对的现状

- `ProfitWorkspacePage.jsx` 的 `workspace-entry-bar` 同时包含标题说明、月份选择、选品工作台及待确认采集链接。后两项已有全局入口，利润标题也在子页重复。
- 月份选择目前就在待移除的顶栏内，不能连同顶栏一起删除功能。店铺选择和相邻视图页签位于 `ProfitViewsContent`。
- 利润页同时存在“成本核对”页签、“ERP 成本核对”通用按钮和按异常直达的按钮，通用导航与处理具体问题的动作需要区分。
- 对新报告流程，“报告与导出”“预览并定稿”以及部分“本月下一步”按钮最终均定位到同一报告区域；旧定稿账本另有原格式导出分支，必须保留。
- Beta.5 侧栏“系统与备份”已直接打开 `/diagnostics`，功能不是缺失；用户仍询问位置，说明入口名称还可更明确。

## 建议范围

### 1. 删除重复顶部栏，合并月份与店铺

- 去掉截图中的整条旧入口栏、重复说明和跨模块快捷链接。
- 保留一个页面主标题“利润核算”，将核算月份和店铺安排在同一页头区域；月份切换在利润明细与成本核对两个视图都可用。
- “利润明细 / 成本核对”保持相邻。当前视图的主要操作紧随其后，窗口较窄时自然换行，不能靠隐藏溢出截掉按钮。
- 保持现有字体、颜色、按钮与内容宽度体系，局部整理间距；不另起视觉风格。

布局方向（示意，不是已实现预览）：

### 2. 精简重复操作与说明

- 普通成本切换统一使用“成本核对”页签；缺成本时仍保留“补齐成本”“人工更正”等直接处理入口，不让用户多找一层。
- 新报告流程保留一个清楚的报告入口，预览、保存、下载集中在报告准备区。已保存、已锁定与待处理状态对应实际可用动作。
- 合并重复的整月下一步和缺成本说明；当前店铺筛选下仍能识别整月未完成项，不能误以为只需定稿当前店铺。
- 长核算说明默认折叠。加载、失败和异常提示保留，正常状态减少占位。
- 旧账本原格式导出、历史报告原文件下载继续可达，不能统一改成滚动定位后丢失功能。

### 3. 系统入口名称更直观（建议项）

建议将侧栏“系统与备份”改为“系统检查”，直接对应用户要找的诊断页面；页内继续并列“系统检查 / 数据备份”。收起侧栏后的提示名称保持一致。不新增一组重复菜单。

### 4. 切换与窗口化体验

- 月份、店铺和视图继续使用已验证的账本上下文；移动控件不产生第二套选择状态，也不因切月份额外重复读取同一台账。
- 快速连续切月份以最后一次选择为准；读取期间明确反馈，旧月份结果不能冒充新月份，保存操作保持正确禁用条件。
- 利润与成本往返保留当前筛选、明细展开和位置；键盘焦点及连续输入不被页头重排打断。
- 使用已有轻量透明度/位移动效；悬停不改变尺寸，支持减少动态效果。此次不修改首页图表布局。

## 业务与实现边界

### 追加调查：台账属性、月份与成本采用（2026-09-22）

本次只读检查用户提供的台账，并运行当前导入/分组代码；未读取或改写正在使用的数据库。诊断脚本位于 `archive/beta6-import-investigation/`，不保存业务表副本。

- **属性展示缺陷已复现**：原表 5,559 行都有“属性集”，当前标准台账导入筛出 5,543 行销售记录、忽略 16 行盘亏，零校验错误，所有销售行均保留属性。`CostMatching.jsx` 的 `expectedSkus` 投影只带 SKU/SKC，后续成本表直接读取匹配对象的 `attribute`，因此显示“未提供属性”。计划从当前账本销售明细补齐显示属性；同 SKU 属性描述冲突须保留可追溯信息，不改变正式成本匹配键，也不要求用户重复导入。
- **月份自动识别尚未实现**：原表“添加时间”全部落在 2026-08。新建导入默认 `previousMonth()`，加载文件未设置文件识别月份；已有账本导入则沿用其月份。计划新建导入根据台账有效日期生成月份建议，单一明确月份自动填入；混月、多文件月份冲突、日期缺失时提示选择，禁止用活动日期、采购日期代替。已有账本月份保持权威，来源月份不一致明确提示；用户主动修改的月份不能被后续异步解析静默覆盖。
- **有候选未采用与缺采购混在一起**：截图的三笔采购 20×4.5、15×4.5、15×4.8，数量加权为 4.59，表格也显示“本次候选待采用”。这能证明该行有候选，不能证明整批具备采用资格；未检查用户实际批次封装。当前只有完整批次才显示采用入口，且 `erpAdoptionReadiness` 要求全部阻塞异常清零，可能连正常行一起阻止采用。截图中顶部仍显示等待回传，亦需复核完整性判定和草稿恢复。
- **最新用户要求（待实施，取代手动采用正常候选的方案）**：用户明确“异常才需要人工”。正常 ERP 成本回传后，自动校验账本月份、SKU 归属和采购证据，通过即采用到当前账本，不要求再手动点击采用。异常单独说明和处理，不阻塞其他合格正常项；批次归属或完整性不合格仍须提示并修复，不能直接放行。人工有效值保持最高优先级，已定稿账本不自动改变。自动接收、校验、采用及重试必须可追溯且幂等；部分成功保留剩余异常，不能将整个批次误标为已完成。

追加验收：真实表只读导入链路核验；属性在成本表/搜索/详情一致；历史月、混月、无日期、多文件及已有账本冲突；正常与异常混合批次、纯缺失、完整性不合格、草稿恢复、部分采用后余项、人工覆盖及定稿保护。涉及部分采用时须先明确 inbox/批次审计及重试契约，再实施与回归，不仅放开前端按钮。

- 成本仍按台账月份取当月及以前最近三笔采购，数量加权、四位截断；利润精确累计后截断。人工更正优先、可撤销；已定稿报告原样保留。
- 代发采用整月总件数，扣款按店铺归集；报告格式与两阶段保存口径不变。
- 涉及利润页容器、共享控制区、报告入口及模块样式，并追加导入月份识别、成本属性展示和采用状态/业务契约。可选系统名称调整仅涉及导航文案和对应检查。当前不计划数据库迁移或云端工作；若部分采用必须新增持久化状态，先补充契约与迁移影响再实施。
- Beta.5 已交付的缓存修复继续使用。十万行原始明细读取、全局失效等更大性能改造单独排期，本版不以布局调整承诺其消失。
