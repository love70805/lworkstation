## 读取契约

- 所有派生缓存统一限制为最多 24 项、单项约 16 MiB、总计约 64 MiB；大小估算按对象遍历并提前停止，不再为了检查大小再次序列化整份数据。
- 界面成本投影仅用于参考展示，按小块读取并剔除 UI 不消费的重复财务载荷；原记录及备份、成本采用和导出路径保持完整。
- 后台恢复仅在稳定输入版本下复用完整原行 SHA256。摘要在事务外分块计算，事务内重读成员、账本、请求、收件和身份；版本不一致、无可靠时钟或有外层事务时回退原权威核验。
- 权威成本采用仍使用完整成本行全部字段。读取限定为同源封装的全部行及本批已验证 SKU 的全部历史，覆盖原有“已有采用”和“较新来源”两个消费者。所有成本批次、原始封装和完整性验证保持。无法归一化的旧 SKU 原样保留，交给原守卫处理。
- 自动建档常驻订阅只保存候选 ID、就绪状态和完整尝试内容的短摘要；实际保存仍在原原子事务中重读所有证据。采购目录去重仅将内部键换为一一对应的本地编号，不丢采购记录或供应商配对。
- 概览中的成本观察在展开后订阅读取，关闭后释放结果。汇总、当前月份、销售图和待办独立显示；展开失败可重试。
- 本地退出日志最多两份、各 256 KiB，只允许版本、时间、页面类型、退出原因/退出码和内存/CPU 数值。无网络上报，不记录 URL、凭据或业务载荷；写入失败不阻断应用。

## 证据限制

原 1.0.0 工作台退出回调丢弃 `reason/exitCode`，现场没有保留原次原因；内存峰值只证明压力路径，不能证明历史事故必为 OOM。隐藏隔离客户端使用原文件只读校验得到的离线副本，允许变更的只有该副本；私有副本、详细计数与 CPU 采样不提交公开仓库。原始业务库、凭据、ERP 登录分区、用户导出均未改写。

首次升级需要重新核验已有回传，因此对照必须同时移除隔离副本中可重建的派生缓存；不能用原版已有恢复摘要的热命中，对比候选首次完整核验。未完成或仪器失败的测量不计入验收通过。
