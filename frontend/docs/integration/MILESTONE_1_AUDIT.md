- 固化 ERP 成本权威、1688 参考及人工审批兜底政策。
- 固化 v8.0 采购记录选择、加权成本、重复成本覆盖和利润公式。

- 修正利润面板和月度账本的人民币显示，并移除“1688 正式成本”错误口径。

## 4. 尚未完成，不得视为正式能力

- 商品库、采集队列、成本核对、月度账本、工作区总览和诊断仍有页面依赖 `demoData`。
- 当前销售导入只保存简化的订单号、店铺、平台 SKU、金额、数量和扣款，尚未完整实现旧利润工具的 SKC/供方货号/属性/变动类型规则。
- 成本领域核心尚未接入 Dexie、云端仓储和页面工作流。
- 月度账本尚未实现创建、唯一月份、草稿、待成本、待审批、定稿和锁定状态机。
- 成本匹配页仍是 1688 原型，应改为 ERP 成本批次核对，并把 1688 兜底放入单独审批流程。
- 商品与供应商数据尚未迁移到统一仓储接口。
- 当前目录还不是 Git 仓库，GitHub、数据库和托管平台资源均未创建。

## 5. 下一里程碑入口条件

下一阶段按以下顺序实施：

1. 建立版本化仓储接口和 Dexie 本地实现，覆盖工作区、商品、SKU、成本批次、审批和月度账本。
2. 将月度台账导入升级为 v8.0 兼容字段、分组和重复替换逻辑。
3. 将成本核对页接入 ERP 成本批次，支持平台 SKU 匹配、异常处理和发布。
4. 将利润面板接入账本状态机、正式成本决策和定稿。
5. 将已定稿结果反馈到商品/选品视图，替换相应演示数据。

在上述闭环通过测试前，不创建生产云资源，也不宣称 Shopeers 已可正式使用。
