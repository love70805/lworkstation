# 0.4.51 大数据整体响应与后台占用

修复人工更正、确认采购价之后后台反复扫描全量销售和历史回传的问题：后台只复查相关依赖发生变化的批次，复用销售基础数据，限制缓存容量；确认事务内全账本销售读取由 3 次减为 1 次。待处理 SKU 超过 30 条时分页，计数与逐项处理范围保持完整。选品档案继续按需补齐，财务写入仍独立核验原始证据、人工优先及月度定稿保护。

## 实测与影响

相同机器分别运行 0.4.50 与 0.4.51 实际安装包提取出的桌面程序，独立配置目录、隐藏窗口；合成数据为 12,000 条销售明细、1,500 SKU、500 条既有人工记录、30 个当前待恢复回传及 30 个异域回传。每组约 15.5 秒（含系统采样开销），合计桌面主进程及后代共 7 个进程。CPU 是窗口内累计执行时间，不是任务管理器百分比；私有内存是窗口结束值，不是峰值或系统物理内存。单次隔离读数不代表所有真实账号。

| 场景与指标 | 0.4.50 | 0.4.51 |
| --- | ---: | ---: |
| 闲置窗口累计 CPU | 1.234 秒 | 0.891 秒 |
| 闲置结束私有内存 | 626 MiB | 547 MiB |
| 人工更正及后续后台累计 CPU | 13.375 秒 | 3.797 秒 |
| 人工更正观测结束私有内存 | 1,094 MiB | 650 MiB |
| 确认采购价及后续后台累计 CPU | 10.563 秒 | 3.453 秒 |
| 确认采购价观测结束私有内存 | 942 MiB | 597 MiB |
| 原生页面确认采购价完成时间 | 0.791 秒 | 0.481 秒 |

原生人工更正场景直接调用相同 repository 保存方法，用于观察提交后负载；确认采购价通过原生页面按钮完成。实际人工表单、零值/微小值和刷新保持另由 headless 用户路径验收。两版本最终金额、确认审计及 60 个回传记录均核对一致。另在最终包 headless 页面确认，单次确认读取销售 12,000 行，旧版为 36,000 行；分页只渲染当前 30 条。
