## 分批实施与契约

1. 可靠性：修复 R1 恢复重试的持久化状态，失败须持续阻断替换；补齐 R2 手动完整导出中的桌面收件/任务，验证实际文件往返。清空入口永久不自动备份的规则保持。
2. 页面响应：先记录大数据下公共汇总与主要页面的读取、可交互时间和主线程长任务；按真实依赖复用精简读取，减少审计/轮询造成的重复扫描，保留工作区/成员隔离、财务核验及失效/失败重试。
3. 成本采集：记录真实采集器合成场景的请求数、并发、首批/总耗时；只优化调度与重复工作，不削减采购历史、范围检查、取消/暂停、限流恢复或来源新鲜度。
4. 仓库整理：审计运行时、构建、测试和文档引用；移除确认不再使用的发布副本/弃用内容，必须保留的旧协议测试夹具移入明确测试目录。保留公开历史交付证据，不重写 Git 历史，不删除本机业务数据、未提交文件或其他任务工作树。
5. RC 交付：建立独立 RC 更新/发布语义；通过完整前端回归/构建、桌面验证、原生 ERP、最终包隐藏用户路径及布局验收、PR/主线 CI，再公开候选并核对元数据和资产哈希。
