# 0.3.0-beta.5 更新计划：流程一致、操作直接、状态可信

日期：2026-09-22。代码基线：`main d50343c` / 已发布 `0.3.0-beta.4`。

状态：用户已明确要求执行本次升级，按本计划实施、测试并统一发布 Beta.5。继续本机 Windows Beta 线；本机暂不安装约定有效。本方案接替[早期规划草案](NEXT_BETA_USABILITY_PLAN.md)，问题事实见[整体检查记录](UI_FLOW_AUDIT_2026_09_22.md)。

## 版本目标与边界

用户从所选账本出发，能按同一月份完成成本、代发、报告与扣款；系统提示与真实可执行动作一致。商品编辑、备份恢复与更新下载能够正确保存、取消和返回。

- 本版修复审查 F01–F21 共 21 项问题，并完成直接相关的入口、准备度、返回位置和反馈优化，内部按依赖拆分，统一验收后发布一个 Beta 版本。
- 首页保留经营概览、每日堆叠、月度簇状、期间店铺构成和 Top 5 SKC；利润页继续专注商品、成本与核算。保留现有左右布局方向，局部减少重复标题、说明和无效留白。
- ERP 成本以台账 `ledger.period` 为准，允许当月及以前，按时间最近三笔、数量加权、四位截断；利润先精确累计、最后截断。人工金额与说明优先、可撤销，真实零与微小正数继续支持。
- 代发仍采用用户给定的整月总件数，汇总加上代发金额；扣款按店铺独立归集。保留已确认的报告样式、未扣款/财务两阶段以及旧文件原样下载。
- 云端部署、跨月对比、新分析面板和独立商品草稿版本不纳入本版。计划不预设新增数据库迁移；真实数据批量修复或迁移需要另列影响和回退方案。

## A · 月份、范围与报告结果一致

覆盖 F01、F12、F13、F14、F20。

1. **沿用当前账本。**从六月账本进入导入、成本、报告仍为六月；新建导入才使用默认月份。工作区/账本校验先完成，再显示可写操作。
2. **返回原处。**取消导入、顶部返回、底部完成使用一致上下文；返回恢复店铺、筛选和原页面。地址中的账本失效时说明原因并选择账本，不能静默切成另一个月。
3. **一套本月状态。**首页流程、利润下一步、定稿准备度使用整月状态；店铺筛选仅改变查看范围。跨月待办单独标明目标月份。已定稿显示查看/下载/补扣款等实际适用操作。
4. **报告利润来源明确。**概览建议采用当前有效财务报告的利润；尚无财务报告时显示已保存的未扣款基础，旁边用简短状态标记。年度汇总标明是否包含未扣款月份。基础重开、来源换版和失效报告不能被“最新文件”规则误选，不改写冻结基础来消除显示差异。

“当前有效”必须匹配工作区/月、`currentBaseReportId` 和当前采用的扣款批次，再按修订取最新。扣款从 20 改成 30、尚未生成新财务报告时，80 只能作为历史报告金额，显示“扣款已更新，待生成”；新报告生成后当前为 70。基础重开后显示重算状态，旧报告可下载，不冒充当前核算结果。优先利用现有报告关联字段，不新增迁移。

验收：系统九月，从六月账本导入和返回始终六月；A 店齐、B 店缺时整月仍未就绪；已定稿不再提示待确认；基础 100、扣款 20 的当前财务报告为 80，概览来源与状态可解释，旧报告仍保留 100/80 原文件。

## B · ERP 与人工更正形成连续流程

覆盖 F03、F04、F05，以及异常处理与回传反馈改善。

1. 将正式有效成本、候选 ERP 成本、原始证据异常分开建模，同一商品的当前采用结果明确可见。
2. 人工更正解决 B 的实际成本后，同批 A 的正常候选允许采用；采用不覆盖 B 的人工值，不把其他尚未解决的异常一起放行。页面准备度和后台提交规则一致。
3. 已采用的成本展示“已采用”、来源和时间；只有存在有效新批次时才出现采用动作。分批回传明确本次收到/可采用/仍缺多少项。
4. 将筛选无结果、成本已齐、缺平台 SKC、没有采购记录、证据不足分别显示，并给对应处理入口。证据不能确认 ERP 未建档时，不猜测原因。
5. 异常、说明和更正入口集中在同一列表；详情侧面打开，窄窗口使用等价弹窗。处理后可以继续下一项，列表位置保留。
6. 通道登记、等待回传、收到批次、待采用、已采用各有真实依据；只有扩展提供采集进度时才显示“采集中”，不将等待视作正在采集，也不将收到视作采用。

采用契约：只把合格的 A 写成正式 ERP 成本；B 保留原异常证据，以人工值生效，不能通过改成 matched 来绕过。ERP 成本按账本 SKU 共用，人工值按店铺生效，因此 B 是否已解决必须检查该账本涉及 B 的全部店铺，不能只看当前筛选。后台事务内复验人工仍有效；采用前撤销、更正后撤销及其他未解决 C 均不能带入错误成本。摘要分别列出本次 ERP 采用、人工有效和仍待处理的项目。

验收：登记 10 个 SKC、分批返回 3 个正常匹配；A 正常/B 人工更正/C 未解决异常能分别处理；后续回传不覆盖人工值；撤销后恢复 ERP 或缺失；重新进入已采用页面不再出现无证据采用报错；空筛选不再诱导重导账本。

## C · 商品编辑、保存与返回一致

覆盖 F06、F07、F08、F09、F10、F11。

1. 正式商品的现有保存动作改为准确的“保存修改”；新建/未入库商品保留草稿语义。本版不新增独立草稿数据库，避免将直接保存包装成“暂存”。
2. 正式保存、确认入库、批量变更在售状态复用相同校验。错误应说明具体缺项，不能通过另一个按钮绕过。
3. 修改后离开编辑器时提供保存、放弃、继续编辑；未改动时不弹额外确认。顶部 ERP/1688 切换保留工作站中的草稿，不应被等同于离开编辑器。
4. 供应商参考预览使用当前草稿报价并正确标为 1688 参考；ERP/人工参考和供应商草稿预览含义清楚，不静默更换正式来源。
5. 标签输入先保留原始文本，确认时归一化；空售价显示待填写，真实零按明确规则处理。
6. 从待采集进入编辑，确认或取消回到同一队列；保留搜索、筛选和位置，已处理项正确移出。商品库、参考视图复用已有返回机制。

保存契约：在 repository 共用规范化商品、参考成本与状态准备度，按状态定义的 `requiresReadiness` 验证，包括自定义状态；批量有不合格项则整批不写并指出具体商品。新商品/采集草稿允许不完整，不自动降级旧商品。未保存保护以最后成功提交的快照为基准，保存失败保留草稿；保存期间继续输入的内容不得误标已保存。覆盖侧栏、面包屑、返回/前进、切商品和刷新，成功保存后的程序跳转不重复询问。

验收：采购价 10→20 时预览立即对应新报价；缺店铺选择在售，任何正式保存路径遵守同一条件；连续输入 `A,B` 可形成两个标签；离开未保存编辑不会无提示丢失；连续处理三条采集无需重复找回队列。

## D · 系统检查、备份与更新可直接使用

覆盖 F02、F15、F16、F17、F18。

1. 侧边栏使用 **系统与备份**，点击默认进入 **系统检查**；顶部直接切换 **数据备份**。相关业务页保留直达连接诊断，支持摘要指引与菜单一致。
2. 系统检查显示本机数据库、存储、ERP/1688 通道、最近检查时间和诊断摘要。读取中、可读取、失败分别表达；不能将数据库可读取写成所有业务都正确。
3. 刷新执行真实读取并更新屏幕结果；检查失败保留错误与重试，不再继续显示硬编码正常。
4. 桌面备份提供明确的“已保存 / 已取消 / 失败”结果。需要回滚保护的恢复必须等备份文件写入成功，再执行已有事务恢复；取消或写入失败保持原业务数据，不能记录为导出成功。
5. 更新下载期间可以取消；失败可重试；关闭更新弹窗、取消下载、稍后安装各自含义明确。继续执行 Beta 通道与版本校验。
6. 本机版把云端迁移、种子包放到高级区域；工作区偏好补充关闭到托盘/退出的直接设置，提示随偏好变化。

验收：侧栏一步进入检查；检查失败后页面能看见失败；备份保存取消/磁盘写入失败不会启动恢复；成功才记录文件和执行恢复；下载未完成可取消并重新下载。所有恢复与下载验收使用隔离桌面资料目录和合成数据。

## E · 页面、键盘、反馈与轻量动效

覆盖 F19、F21，并完成报告准备度与返回位置改善。

1. 利润页收敛为月份/店铺、主要操作、明细与报告区域；只突出当前最重要的下一步，详细解释按需展开。
2. 报告预览前列出缺成本、代发是否登记、哪些店铺缺扣款，缺项直接到处理处。未扣款和财务报告入口清楚，最新文件直接可下载，历史修订折叠。
3. 读取完成前保留占位，不显示假零、假空或“工作正常”；失败局部重试。已存在的上次结果可以保留，但需注明正在更新或读取失败。
4. 进入销售详情接收键盘焦点；Escape 返回原柱子；分页回列表首行；利润/成本往返恢复展开、页码和位置。多店图例限高，窗口变窄时关键操作仍可达。
5. 按钮反馈约 100–150ms，弹窗/侧面详情约 160–220ms，使用轻微位移与透明度；鼠标悬停不改变图表尺寸。支持减少动态效果，不延迟保存、不重置输入焦点。

验收：正常/空/读取中/失败/已定稿五类状态均有可执行路径；1024/1280/1440 窗口、浅深色及 Windows 125%/150% 缩放；键盘和鼠标都能完成关键任务；输入多位数保持焦点。

## F · 加载与后台恢复验证

本版必做测量和已发现的重复工作修复；更大范围的缓存失效策略改造由测量决定。

- 对 1 万/10 万行合成数据记录：首次计算、同月返回、重启缓存命中、修改单店成本后的重算；区分存储读取、计算与渲染耗时。
- 优先消除可证实的重复读取/重算，确保已有持久缓存实际生效。若需从全局版本改成工作区/月/依赖失效，必须同时覆盖导入、成本采用、人工撤销、费率、备份恢复和规则升级。
- 同机同数据比较前后耗时，记录完整页面可用时间，不以一个计算函数提速代替用户体验。300ms 内开始反馈是交互目标，不承诺十万行完整核算在该时间完成。
- 验证 ERP/1688 切换、最小化、睡眠与恢复；用有限本机诊断区分崩溃、无内容、响应超时。健康表单不因短暂后台状态自动刷新。
- 偶发白屏若仍无法自然复现，记录具体覆盖场景和限制；不能仅凭故障注入或一次成功返回宣称彻底解决。

以上阶段是同一版本内部实施步骤，不逐阶段发布。涉及广泛共享组件或数据规则的未解决问题必须先修复，不能以界面看起来正常替代验收。

## 发布必须通过的用户路径

1. 六月账本 → 同月导入 → 预览 → 取消/完成 → 原月份及店铺保持一致。
2. ERP 正常 A + 异常 B → 人工更正 B → 采用 A → 返回查看已采用 → 新回传不覆盖 B → 撤销 B 正确恢复来源；另测同 SKU 跨店人工范围及采用期间撤销。
3. 筛选缺成本直到最后一项处理完 → 显示完成，不误报 SKC 缺失；定稿仍检查整月。
4. 商品改价/状态 → 实时参考预览 → 合法保存 → 重新打开一致；不合法在售被各路径统一拦截；未保存离开可撤销。
5. 台账与成本齐 → 登记整月代发 → 保存未扣款报告 → 后补各店扣款 → 保存财务报告 → 概览采用正确有效结果 → 换扣款批次/重开基础后旧报告不再冒充当前 → 旧文件不变。
6. 系统检查 → 故障状态/重试 → 备份取消/成功/失败 → 隔离恢复 → 更新下载取消/重试，反馈与实际结果一致。
7. 第 2 页展开商品 → 往返处理 → 保留位置；柱状图 Enter → 期间明细 → Escape 返回；浅深色、窄窗口和缩放可用。
8. 重启缓存读取、单项更新重算、ERP/1688 后台恢复，数据正确与表单保留同时通过。
