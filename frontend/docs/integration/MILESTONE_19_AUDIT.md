# 里程碑 19：同步服务运行时与 PostgreSQL 恢复/种子适配

状态：本地 Beta 已具备可注入 PostgreSQL 连接池的同步服务运行时  
审计日期：2026-08-08

## 本次目标

把同步 API 从单文件内存开发脚本拆成可替换运行时，使同一套 HTTP 合同可以连接内存后端或真实 PostgreSQL 后端。

## 服务运行时

- `syncServiceRuntime.js` 提供统一的健康检查、审计同步、恢复、种子预检和种子导入路由执行器。
- 内存运行时继续供本地开发和冒烟使用，行为与原 API 兼容。
- PostgreSQL 运行时要求注入连接池、授权器、恢复仓库和种子仓库，不会在缺少适配器时假装功能可用。
- 每次 PostgreSQL 请求都通过 `pool.connect()` 获取专用客户端，在同一客户端完成事务，最终无论成功或失败都 `release()`。
- 未知路由返回结构化 404；服务端异常默认按 5xx 和可重试错误处理，不再把数据库故障伪装成普通请求错误。

## PostgreSQL 读写适配

- `syncPostgresPlan.js`：增量事件的幂等、冲突和业务事务写入。
- `syncPostgresRecovery.js`：在 `repeatable read read only` 事务中读取工作区全量基线和审计事件，生成 `shopeers-sync-recovery v1`。
- `syncPostgresSeed.js`：种子预检、指纹幂等、预检版本校验、批量事务导入和管理员成员初始化。
- `cloud_seed_imports`：记录工作区种子指纹、导入版本、计数和表统计，受工作区 RLS 保护。

恢复基线直接来自当前 PostgreSQL 数据，而不是依赖服务进程内存，因此服务重启或部署到新实例后仍可恢复。

## 权限与边界

- 业务授权仍由注入的 `authorize` 完成，浏览器 `actorId` 不能替代服务端身份。
- 种子导入要求管理员 actor；实际部署应使用经过 JWT 校验的用户 ID，并由服务端受控数据库连接执行初始化写入。
- 当前未创建 Supabase、PostgreSQL、Auth、对象存储或托管项目，也未上传真实工作区数据。
- `pool` 必须连接到已执行最新迁移的数据库；缺少 `cloud_seed_imports` 或适配器时接口明确返回 `503 SERVICE_NOT_CONFIGURED`。

## 验收证据

- Vitest：新增运行时、恢复仓库和种子仓库测试，覆盖连接释放、提交、回滚、重复导入和预检过期。
- HTTP 冒烟：健康检查、审计同步、重复同步、授权、恢复、种子预检/导入和恢复基线均通过。
- PostgreSQL 迁移静态合同：表、工作区字段、RLS、不可变事实保护和种子导入元数据均通过。

## 当前阶段

项目已从“本地内存同步参考实现”进入“可接入真实数据库的服务适配阶段”。剩余工作是选择并批准实际云端供应商，配置 JWT/Auth、连接池、RLS 集成测试、对象存储和部署流水线；这些属于外部资源操作，尚未执行。
