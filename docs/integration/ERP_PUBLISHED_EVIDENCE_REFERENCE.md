# 已采用 ERP 成本证据引用修复

## 现场与根因

Beta.7 现场同一平台 SKU 显示“当前采用：¥4.5900 · ERP”，正式成本已生效；展开采购证据却提示缺少 `evidenceRef`，并建议重新采集。完整 v2 批次在接收和采用前均经过证据引用校验，但正式成本行持久化时遗漏了 `evidenceRef` 和 `evidenceComplete`。再次打开成本页使用已保存行重建证据详情，于是把已采用的完整证据误报为缺失。

## 契约与影响

- 新采用行从已验证的源行及唯一仓库证据写入 `evidenceRef` 和 `evidenceComplete`。完整 v2 的缺失或错配引用继续被拒绝，成本计算及采用规则不变。
- Beta.7 已发布行读取时，仅当批次仍为 `published`、工作区/账本/请求/源批次一致、查询 SKC 匹配、同仓库证据唯一且完整、采购及排除记录一致时，才从已保存的 `sourceContract` 投影这两个字段。投影不写回数据库；证据不足时保留原缺失状态。
- 撤回批次保留最新行墓碑规则，不恢复旧成本；人工更正、定稿报告和正式金额不受影响。
- 已采用 ERP 的成本详情明确说明无需人工确认，人工更正仅用于确需修改的情况。

## 验收信号

11 条采购记录中最近三条 20×4.5、15×4.5、15×4.8 采用 4.5900 元。保存后重新读取并展开证据详情，不出现缺少 `evidenceRef` 的伪异常；对 Beta.7 旧行能只读恢复。范围不匹配、证据重复或不完整、采购记录不一致、撤回批次均不得恢复引用。
