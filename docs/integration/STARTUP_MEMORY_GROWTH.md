# 启动后无操作内存增长

基线：origin/main `8b1d8ee` / 0.4.14。用户报告启动后没有操作，内存持续增长。

## 证据与范围

只读进程采样确认工作台 renderer 私有内存约 2.5–3.1 GiB，CPU 持续繁忙；原应用未被关闭、重启或修改。ERP 六批成本及资料已确认。只读一致文件副本在隔离 profile 中检查：8657 台账行、110 商品、367 ERP 成本、7 异常，三个 partial 批次。副本及原始分析仅存本机忽略目录，不提交业务原始数据。

partial 恢复计算已有幂等判断，但最后仍无条件更新关联 ERP 批次的 adoption。这会触发全局财务来源版本失效，重新计算预存资料与主页参考，重复克隆采购证据。回归复现三轮无变化恢复三次写入。

## 契约与验收信号

- 仅 adoption 实际变化或旧批次缺少该元数据时同步批次；无变化恢复不产生业务写入或来源版本变动。
- 成功且全程无来源变化的恢复检查可复用一个内存结果；财务/成员来源版本变化或失败时重新检查，不跨重启复用。
- 后台进度回报读取仅包含采用状态/计数的小投影，按财务来源版本复用，不反复克隆采购封装。主页复用既有 compact 参考投影，与预存检查共用。
- 保留异常约束、异常重试、新证据、人工优先、撤销恢复和已定稿保护；不把价格异常自动采用。
- 不增加业务 schema 或迁移，不改写真实库/队列，不安装。
- 隔离回归证明无变化 partial 多轮恢复不写入、不触发 live query；实际变化仍可观察并持久化。
- 使用同一份只读副本、相同入口和 Electron 环境比较启动与空闲。记录私有内存、JS heap、CPU 和页面可见性，不强制 GC；超过诊断内存上限提前退出隔离程序。

实现 `1a71336`。174 文件 / 1367 前端测试通过。真实数据副本原版 40 秒 Electron 私有内存 1548.4 MiB；修复源版同入口 425.1 MiB，181 秒空闲范围 414.9–428.3 MiB，不强制 GC、全部隐藏。上述不含独立 Node 收件服务，候选验收须另记录完整进程树。真实原库/队列未修改。

状态：修复和源版持续空闲已通过，0.4.15 候选与发布验收进行中；尚未公开。
