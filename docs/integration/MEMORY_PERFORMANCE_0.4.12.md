# 0.4.12 启动与空闲内存优化

日期：2026-10-08。用户确认刚启动或空闲时占用高。基线 origin/main `9a1131e` / 0.4.11；独立托管工作树 memory-performance，分支 codex/v0412-memory-performance。旧主工作区的未提交规划及 Infinite Canvas 保留。

启动此前同时创建工作台、ERP、1688 及两个扩展，即使外部页面从未使用也保持后台运行。本批将外部页面与扩展推迟到首次进入；已打开的页面继续保留登录态、输入、采集与心跳，不自动回收正在使用的页面。

影响：桌面页面生命周期及工作区安全配置协调。未打开页面可明确延迟配置；第一次打开时使用最新已提交工作区配置，成功后才导航。同一页面的并发打开合并为一次初始化，迟到初始化不改变用户当前标签；失败释放页面及扩展并可重试，退出过程不重建页面。首次加载与失败复用壳层的中文提示及重试，未打开 ERP 使用待使用状态。

空收件/租约文件读取直接返回空快照，首次写入或外部创建文件后仍由真实存储 Worker 读取、校验与原子落盘，避免为空队列常驻线程。工作台数据、原始收件证据、成本、定稿与数据库结构不变。

验收信号：相同机器/运行时/合成页面的三轮全新 profile 启动与空闲进程私有内存、工作集和进程数对比；冷启动无 ERP/1688 页面或扩展；首次进入、快速切换、失败恢复、工作区切换配置、登录态/草稿及后台采集通过。完整前端/桌面门禁、隐藏候选与公开资产回读后统一稳定发布，不自动安装或改写真实业务数据。

## 同机测量

Electron 44.2.0、真实生产前端、空本机队列、新 profile，外部页面为不额外分配内存的固定隔离 HTML。工作台可用后 10 秒测启动，再空闲 20 秒。PowerShell 累计所有 Electron 进程与独立收件进程的 Windows 私有内存；工作集另存原始 JSON，不能相加后当作独占物理内存。没有强制 GC、清用户缓存或禁用 GPU。

| 三轮，单位 MiB | 0.4.11 基线 | 本批源码 |
| --- | --- | --- |
| 启动私有内存 | 524.9 / 527.8 / 536.3 | 345.2 / 356.4 / 351.1 |
| 空闲私有内存 | 491.1 / 488.9 / 499.6 | 333.3 / 343.1 / 337.0 |
| 渲染进程数 | 6 | 2 |

中位数：启动 527.8 → 351.1 MiB，降低 33.5%；空闲 491.1 → 337.0 MiB，降低 31.4%。原始结果为 `archive/memory-performance/baseline.json`、`final-source.json`。另有延迟外部页面的分步测量 `optimized.json`；短空闲故障回归 `final-behavior.json` 不作为上述基准。

隔离页面测量不等同于真实登录 ERP、1688 或真实大队列的绝对占用；打开页面后仍保留其进程和任务，未承诺打开全部页面后同样节省，或自动收回真实业务证据。最终候选结果见 [发布记录](../RELEASE_0.4.12.md)。
