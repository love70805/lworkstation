# 0.4.14 已送达 ERP 成本接收修复

2026-10-09 11:24:54（UTC+8）：Windows 稳定版已公开为 [GitHub Latest](https://github.com/love70805/lworkstation/releases/tag/v0.4.14)。四公开资产匿名完整回读及生产更新入口通过；本机未安装，真实收件队列、账本和 ERP 账号未操作。

修复成本已经采集并送达、资料检查也完成，但利润页仍显示零有效成本的问题。App 原先在尚未取得本地登记 SKU/SKC 范围时提前解析精确范围回传，使有效成本不能进入持久接收器。现在由接收器读取已登记请求后执行原有严格校验、保存、自动采用及回执；更新后可直接接收现有待收回传。

成本处理失败在当前工作区的跨页面提示中显示具体原因，可返回对应账本的成本核对；任务已结束也不会隐藏处理错误。断联保留原错误，健康接收周期清除。连接失败继续由已有任务状态提示表示，不把无任务的空闲页面标成成本处理失败。完成任务移除残留“当前阶段：补充资料”。

原价格异常约束、人工更正优先、定稿保护、工作区与登记范围保持。图片、供应商链接和预存资料冲突不成为正常 ERP 成本核算的前提；ERP Assistant 保持 8.0.39，无需业务迁移。预存区“资料来源冲突”指同一 SKU 的 SKC / 属性来源值不一致，需要核对商品分支；不能据此判断为重复 SKU，也不自动选择来源或更改归属。

只读现有队列确认六批成本 pending、六批资料 acknowledged；六批原始成本封套在登记上下文下全部通过，旧无上下文预解析全部失败。保持原始封套不变，在 fake-indexeddb 与合成账本中通过实际 App 默认轮询接收六批 / 374 SKU：367 自动采用，7 价格异常待核对（5 涉及单价 1，2 涉及近期采购价明显偏低）。重复执行没有重复成本、批次或审计；没有确认真实队列或改写真实业务库。该结果是隔离验收，现场采用仍按当前账本、人工成本和定稿状态核对。
