# 0.2.10 成本回传与经营首页更新

用户于 2026-09-10 在逐项确认下列规则后要求“执行版本更新”。本文件为实施合同，不是已发布声明。

## 基线、目标与非目标

- 基线：`3d364acddeb1a3894a0950ef2ffa48216080929c`，集成分支 `codex/selection-profit-erp-sync`；公开稳定版 0.2.9。
- 目标：确定 SKC 即准备回传；成本传递可观察、可恢复；人工更正可直接参与精确利润；经营首页承接利润流程；首次安装可选路径。
- 非目标：不改收入/仓储公式，不把旧 1688 参考审批自动提升为正式成本，不覆盖已定稿快照，不执行线上 SQL，不操作真实 ERP 账号或改写用户业务数据。
- 临时工作区位于 `.worktrees/release-0.2.10/`；主线只编写合同/发布元数据、审查及集成。现有利润与 ERP、桌面化任务承接实施。

## A. 请求与传递合同（利润与 ERP 主责）

当前问题：CostMatching.copySkcs 才登记请求；自动加载 effect 被非空 sourceText 拦住；后台只接受完整相等 SKC；扩展复制/CSV 的“预览单件成本”不是导入别名；采集结束提示未等待送达。

1. 当当前账本、工作区和非空待查 SKC 集合确定时，自动幂等登记 request；复制是纯便利动作。集合变化取消/替代旧关联，防止异步响应串账。定稿账本不产生新的核算写入。
2. 保留认证、工作区、ledgerId、requestId 与查询时间校验。允许在已登记集合内分批/单个 SKC 查询；必须验证非空子集及原始证据归属，不允许超出请求集合。多请求歧义不能猜账本。更新扩展、服务端、domain 和 repository 对应校验及 tests，不能仅放松单层。
3. 后台接收保存独立于手动草稿。存在草稿时提示已收到新批次，提供保留草稿/查看返回结果/明确丢弃草稿载入；清空草稿同步清除持久草稿，不能下次自动复活。重复送达保持幂等，分批结果不丢失已匹配 SKU。
4. 显示采集、待发送/发送失败、服务端已接收、待核对/已应用等真实阶段。失败保留可重试数据；未接收不能声称成功。完整持久证据不依赖采购页面打开。现场尚未确定的原因不得宣称已复现修复。
5. 复制用于工作台导入时优先提供带完整证据的现有 versioned JSON envelope；保留 TSV/CSV 兼容并识别“预览单件成本/预览次数/预览日期范围”。能解析与能按 ERP 原始证据发布是不同状态，不能伪造完整证据。文本导入不完整时可走用户确认的人工更正。
6. 每条待处理 SKU 显示有依据的原因和可达操作：零价、ERP 未建档、无采购记录、尚未收到、发送失败、证据不完整、原因待查。仅有缺失不能推断 ERP 未建档。

## B. 人工更正合同（利润与 ERP 主责，含必要同步适配）

- 仅输入非负有限 CNY 单件成本和非空更正说明；不强制附件、链接、来源表单或额外复核人。操作人从成员上下文获取，遵守已有财务写权限，不新增提权。
- 显式人工更正优先于 ERP，允许 0 和微小正数，参加精确核算；不把缺失转换为 0。现有精确累计/最后截断保留，不提前截断人工小数为 0。
- 作用域为 workspaceId + ledgerId（当前月/店账本）+ canonical SKU；如历史账本包含多店，需明确 store scope 并覆盖所有读取/定稿/同步路径，不能从页面筛选推断保存作用域。
- 保存原值/新值/说明/操作人/时间，可撤销；撤销恢复最新可用 ERP，缺失则待补。ERP 后续数据仍保存，但不能覆盖人工有效值。审计和核算在同一事务完成。
- 使用明确的新人工类型标记，如 referenceSnapshot.kind = manual_override；旧 approved_1688 记录保持参考语义。最终 decision.source 使用 manual_override，不能冒充 erp。更新 policy/formula 版本而不重算旧定稿。
- 复用 costApprovals/audit 容器；新增事件需要同步 registry、plan、recovery、seed/backup 往返和权限测试。不把只有本地生效的更正当作完整交付。SQL 若需兼容零价/人工来源，先报告精确追加迁移内容；本轮不执行在线迁移。
- 已定稿/锁定账本写入口均拒绝修改；通过现有显式重开流程后允许。UI、repository、导出和定稿选择相同成本，撤销/更正后摘要刷新。

## C. 首页整合与跨页上下文

- 利润与 ERP：将 ProfitPanel 提供为可嵌入的内容组件（默认页面仍兼容），如 export ProfitWorkspaceContent；内嵌模式不再套 AppShell，不另造公式，简化主要操作、默认折叠明细和低频操作。负责 MonthlyLedger、CostMatching、profitFilter 等业务跳转和上下文适配。
- UI 适配：WorkspacePortal 嵌入该内容，保留有用的经营入口但不重复整页利润面板；侧栏工作区首页/月度账本/成本核对/选品独立，移除单独利润入口；旧 /profit?ledger=... 兼容跳到 /workspace 并保留参数。上下文用已有 ledger 查询键，跳转携带已校验的 ledger 和必要筛选，不能跨工作区泄漏。
- 全局 UI 专职当前在本机列表/归档/索引中不可用，不新建长期任务。将上述边界清晰的 AppShell/App 路由/WorkspacePortal 组合适配交由桌面化现有任务，作为本次显式跨模块适配；ProfitPanel 及全部业务逻辑仅利润与 ERP 修改。桌面任务从合同开始，不同时改写利润文件。
- 普通 Windows 窗口 1024×768/1280×800 与窄屏检查按钮、弹窗和表格；表格可独立滚动，主要操作不得靠全屏才可点。

## D. 桌面化主责

- 首次安装改 assisted NSIS，显示路径选择，默认当前用户安装；后续升级沿用现有路径、数据与快捷方式，支持自定义含中文/空格路径。保留稳定/Beta 通道隔离和既有 QA 独立安装身份。本次只发布稳定版，不改变公开历史 Beta 与稳定包共享 appId 的兼容事实，不新增 Beta 身份迁移。
- 安装位置只影响程序，不迁移 AppData；deleteAppDataOnUninstall 保持 false。禁止通过构建意外自动发布。
- 左上角版本弹窗紧凑设计，保留版本、通道、检查/下载/安装与错误反馈；适配窗口边界。根据实际所有权修改 desktop popover，必要前端版本卡一并检查。
- 更新仍默认检查开启、下载和重启安装显式操作；验证原安装目录升级和新安装向导，不能只验证 package JSON。
