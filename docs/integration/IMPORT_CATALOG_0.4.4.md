# v0.4.4 导入与基础档案契约

2026-10-07，基线 origin/main be8ad17 / 稳定 v0.4.3。用户已批准本对话整理的六项需求实施，完成后统一稳定发布，本机暂不安装。

- 整批按货号末尾匹配后缀，NFKC 与英文大小写归一化只用于匹配，不修改货号。输入后显式应用，替换各文件的选择；新增文件沿用已应用后缀，单店仍可覆盖。零命中不能退回全选；现有关键词选择与成功记忆保留。
- 导入操作区固定在首屏并在滚动时可用；SKC 影响明细默认折叠，概览仍明确新增、覆盖和移除数。覆盖确认绑定原预览签名，修改配置立即失效。
- 台账导入与基础建档在同一 Dexie 事务内完成；只处理本批有效行，SKU 全工作区唯一，SKC 为父级。重复导入不重复建档；已有资料、价格、成本和业务状态保持。缺 SKC、多父级/店铺/属性、重复父级或不可访问归属列为建档待处理，不能猜测、覆盖或阻塞其他有效档案。
- 新档案是待补全草稿，名称使用既有“未命名商品”占位，图片/供应商/售价/成本留缺；编辑时沿用既有 ERP 补充资料投影。来源记录账本、月份、批次。审计使用现有 product_created/product_updated 完整快照，备份与恢复契约保持，不新增数据库迁移，不对历史真实库批量补档。
- 参考页默认未建档；仍可显式查看全部或已建档历史。旧版本自动存下的“全部”默认值首次升级为未建档，后续明确选择按 v2 标记记忆。按 SKU 关联过滤后再按 SKC 分组，部分建档不能隐藏未关联分支。
- v0.4.3 已有分批采集、全局最多八路请求、固定任务归属、暂停/恢复/重试与正常成本自动采用。本批保留并回归这些能力；不增加多页面或无限并发，不改变正式成本、人工优先和定稿保护。

并发可行性判断：现有 ERP 采集器已并行读取两路采购列表，并在受控请求池内同时补取商品/采购详情；批次先交付成本，再补充资料。多开页面会引入重复请求、跨页面总并发失控、租约/登录状态和回执归属竞争；没有证据表明页面数量是当前瓶颈，不能据此承诺更快。本轮采用已有单任务受控并发和持久化恢复，验收请求数、首批交付、并发上限、暂停/取消/限流及回执恢复；若后续现场日志表明具体阶段是瓶颈，再对该阶段调整队列或调度。

验收：整批与单店例外、后缀零命中/大小写/全半角/新增文件、覆盖确认失效、长明细与首屏/窄屏/主题/键盘；分块台账建档、幂等、已有资料、归属冲突、整批取消/失败回滚、审计/备份恢复；既有 ERP 分批、限流、恢复、回执与成本保护。通过前端全量、构建、适用桌面/候选、CI、公开资产及更新入口回读后标记发布。
