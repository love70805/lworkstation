## 当前问题及目标交互

- 现有 `SalesAnalytics` 的柱子为无点击事件的 div，仅有原生 title；下方按整月 SKU 汇总并直接拼接活动原文。不能把整月 SKU 表误作为选中日明细。
- 保留“销售额 / 销量”两按钮，金额和数量在悬停/焦点/选择摘要中同步显示。日期按台账添加日期/Asia-Shanghai 既有解析规则，不能替换为交易日期或导入当天。
- 点击日期选中柱子并打开右侧非模态当天明细；容器不足时自然放到图表下方，避免遮挡和嵌套大滚动区。提供明确关闭/返回全月，键盘能选择日期和退出明细。
- 当天明细按店铺 + 平台 SKU 聚合，展示 SKU、属性、店铺、销量、销售原额及均价；可查找 SKU/店铺/属性，可按销量或销售额排序。搜索不改变当日合计，列表明确显示筛选范围。较多商品分页或虚拟化，避免一次渲染完整月度大表。
- 活动主表不显示长文。使用“活动详情 · N 条”等中性入口，默认收起；展开后简短摘要，原文按需查看。无法可靠解析活动名时使用条数/截短原文，不猜测活动含义；缺失显示待查，不能当作未参加。
- 图表给出刻度、零线与日期；正常桌面容器完整显示月内日期、按宽度减少日期标签，避免常驻横向滚动条。负数向零线下方绘制，不用绝对值柱高冒充正值。已知零与日期缺失区分，未知空白不能填零。
- 更换工作区/账本/月份/店铺立即清空旧选中日和商品明细；异步返回需核验完整 scope，晚到的旧请求不能覆盖当前画面。重开同日或切换指标不重复计算整月，hover 不读取数据库。

## 共享组件与只读数据 contract

- `SalesAnalytics({ workspaceId, ledgerId, store='all', stores=[], onStoreChange })`：store 为父层唯一受控范围。stores 来自父层已验证的当前账本店铺清单。onStoreChange(nextStore) 可返回 void/Promise；组件展示等待/错误，不另造一份与父层不一致的店铺状态。无 callback 的兼容调用只展示现有范围。
- 利润入口适配：使用 `ProfitViewsContent` 的 stores 与 `change(view, nextStore)`。首页适配：使用 `ledgerScope.context.stores` 与 `ledgerScope.change('store', nextStore)`。保留现有月份、路由和其他筛选参数；上方原有店铺控件与每日销售新控件必须同步。
- 保持 `readLedgerSalesAnalytics` 的现有返回与精确累计口径兼容。新增只读 `readLedgerDailySalesDetails({workspaceId, ledgerId, store='all', date})`（date 为目标月合法 YYYY-MM-DD）和纯 domain 聚合辅助；只读取当前活动工作区内、指定账本与店铺的符合原销售语义的记录，拒绝非法/跨月日期及外工作区/外账本/不存在店铺。
- 日明细返回当前日期、scope、状态（有数据/已知零/待查）、精确日合计和按店铺+SKU聚合的商品 rows。数量/销售额/均价沿用十进制字符串，先精确累计最后展示截断；仅图形坐标可转 Number。属性/原始活动来源只服务于当前日和店铺，不混入其他日/月数据。
- 无新增持久字段、迁移或写入接口。可针对性能拆分纯 helper/组件，但不要放宽权限校验、修改总账或缓存真实业务数据到仓库。店铺列表不能为空时自动猜选不在本轮范围。
