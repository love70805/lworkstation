# ERP 任务接收确认与重连

用户于 2026-11-03 报告工作台已发出任务但 ERP 插件显示未收到，重进后才成功。实际联网核对主线与稳定版本为 `62d2471d95504267194e10670b47068c7ee1a2f5`（1.0.10），使用独立执行树处理。现场仍运行 1.0.9，当前任务索引与完整增量日志没有保留任务，不能倒推该次故障触发源。

## 已确认与契约

- 合成复现确认：已登记但未被执行者认领的任务会一直停在 ready，重复启动复用原页面且按钮被当作采集中禁用；隐藏页等待 managed UI 配置回调也可能永不启动。
- 桌面区分等待接收与实际执行；未接收时有限等待、自动重建一次，仍无确认时给出可手动重连的状态。登录、暂停、停止、工作区切换及已认领执行者有明确优先级。
- 原子 reconnect 控制仅允许当前 ready、无执行者且接收意图匹配的桌面任务，轮换接收意图，不改任务身份、范围、批次尝试或回执。已被接手或人为暂停的任务拒绝该操作。
- 隐藏页绑定 requestId 与 resumeRequestId，旧页面不能通过重新查询接收新意图。重连保留已送达批次，人工有效成本、完整历史和定稿保护沿用原合同。
- 页面加载及探针有界；迟到响应不能复活旧工作区或影响新执行者。插件初始化不依赖无期限的配置回调。
- 用户追加要求：默认成本采集不整理商品资料。新建和显式继续成本均使用 `on_demand`；成本收件保存完整核验证据，但附带商品信息不自动投影到商品资料。商品资料仅由明确的手动资料请求整理，旧批次回执及正式成本不重写。
- 手动资料复用本任务的确定资料请求；存在同 SKC 的多个月份旧请求时，不再通过查询时间猜测来源。成本已完成时仍保护资料执行者；页面 load 超时先原子核对接收意图，已认领页面继续监测。
