# ERP 实际采集提速与映射追查（0.4.42）

目标：继续压缩成本采集的实际读取耗时，逐项查清上一任务目标 SKU 映射未确认的原因；原任务规模不公开。实际联网核对主线基线 `b3b5593d47fb6987c6fb8e3eaa3fdd7b6026a0a5`，现有稳定版 0.4.41。

## 范围与契约

- 优化 ERP 只读采集调度、同次任务中的重复请求及映射发现；保持完整目标采购历史、分页与总数检查、取消单排除、准确 SKU/SKC/仓库身份、限流退避及原有持久回执。
- 先核实跨批次缓存是否已经复用，不把各批次累计统计当作实际网络请求数，不通过省略必要证据、放宽匹配或减少历史完整性换取速度。
- 同一读取过程可以复用已完整读取的原始证据；新任务、重启、登录变化及暂停后恢复沿原有重新核验要求。
- 映射缺项的真实原始响应与逐项分析只放忽略归档，不公开业务标识或账号材料。现场数据库、队列、检查点与 ERP 商品映射保持只读。

## 调查

历史诊断表明同次任务已经存在缓存复用，累计订单、页数和明细计数不能直接当作网络请求次数。目标异常属于映射未找到，目录完整且采购明细无失败；具体业务规模不公开。只读分析使用既有收件及内置 ERP 已保存的业务接口响应，未读取登录凭据或 HTTP 认证元数据。

缓存中存在精确 SKU/SKC 对及其旧仓库关系，但旧仓库不在对应 SKC 商品目录中；旧采集器仅从目录发现仓库，因此漏查映射。原始响应隔离回放能复现此路径；缓存响应带 `temporary=1`，不能据此证明当前关联仍有效，标记含义也未独立确认。现场核对未取得有效的当前映射证据，不将历史缓存称作当前核验结果。商品标识、数量、业务时间和逐项原始证据仅存本机忽略归档 `archive/erp-collection-speed-20261018/`。

## 实现与验证

- 采购列表分页期间提前读取已取得订单的明细；同一批次共享在途请求，同次任务继续复用已完整读取的原始证据。全局请求从 8 路按健康响应逐步升至最多 12 路；限流降至 2 路并遵守退避，冷却后恢复，修复一次限流后整次任务一直停留两路的问题。
- 高频进度绘制合并为最多每 100 毫秒一次。新权威读取禁用浏览器 HTTP 缓存；记录实际请求次数、重试、限流、并发峰值和累计请求耗时，后者有并行重叠，不能等同任务历时。
- SKC 目录重试后仍缺少的规格，使用已有 `skuGroup` 接口按平台 SKU 精确补查；必须再次验证完整 SKU/SKC/仓库关系，并完整读取新发现仓库的采购历史。不用历史缓存猜测当前关联或正式成本。返回为空、目录不完整和精确关系未确认分别报告。
- 对照同一 10 SKC × 48 订单、50 毫秒接口延迟：旧版 6079 毫秒，新版 4330 毫秒，耗时缩短约 29%；请求均为 560 次，完整采购记录和成本结果摘要一致，峰值 8 → 12。该结果来自隔离受控场景，不代表真实 233 SKC 已重跑或承诺其具体分钟数。
