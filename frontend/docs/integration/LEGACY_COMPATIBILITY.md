# 旧工具兼容契约

本文件把 ERP Assistant v8.0 和选品工作台 v0.0.1-beta.2 的关键行为转换为 Shopeers 的验收契约。

## 1. ERP 成本抓取契约

### 1.1 查询上下文

- 查询单位是平台 SKC。
- 扩展必须捕获用户在 ERP 采购管理页实际发出的采购列表请求。
- 复用全部筛选参数，只替换分页参数。
- 未捕获真实查询、分页总数不一致、任一明细请求失败或任一 SKU 映射失败时，整个成本任务失败。
- 失败任务不得发布、复制或导出部分结果。

### 1.2 合格采购记录

采购记录进入成本选择前必须满足：

- 采购单不是状态 `11`。
- 有有效采购日期，且不属于当前自然月。
- 有仓库 SKU。
- 采购数量大于 0。
- 单价或可推导单价的金额有效。

### 1.3 记录选择

同一仓库 SKU 的合格记录按日期从新到旧排序：

1. 如果存在真实 1688 单号，只取最近最多 3 条真实 1688 记录。
2. 真实 1688 记录不足 3 条时不使用普通采购记录补齐。
3. 只有完全没有真实 1688 记录时，才取最近最多 3 条普通采购记录。
4. 成本和输出单号必须来自同一批入选记录。

### 1.4 成本和映射

- 单件成本使用入选记录的数量加权平均。
- 一个仓库 SKU 可以产生多个平台 SKU 成本行。
- ERP 未返回平台 SKU 映射时，兼容输出允许用仓库 SKU 作为平台 SKU 兜底，但必须标记 `mappingFallback=true`。
- Shopeers 入库时应把兜底映射列为待核对，不得把它当成已经确认的平台 SKU 主数据。

### 1.5 兼容 TSV

兼容输入列：

```text
平台SKU	仓库SKU	1688单号	单件平均成本
```

第三列可以是普通采购单号兜底。新系统应额外保存单号类型，而不是仅凭字符串猜测。

## 2. 月度台账导入契约

### 2.1 文件与店铺

- 支持 CSV 和 XLSX。
- 文件名去除扩展名后作为默认店铺名，用户可在确认前修改。
- 保存原文件名、文件哈希、导入时间和字段映射。

### 2.2 字段识别

至少兼容以下语义字段：

- 供方货号 / 货号 / 商家编码
- SKC / 商品 SKC
- 平台 SKU / 商家 SKU / SKU
- 属性集 / 属性 / 规格 / 颜色
- 变动类型
- 数量 / 件数 / 购买数量
- 客单发货 / 平台客单
- 金额 / 实付金额 / 单据金额
- 客单金额 / 平台金额
- 1688 单号
- 单件平均成本 / 单件成本
- 客退罚款

### 2.3 分组与替换

- 一级键：`店铺 + (SKC || 供方货号) + 供方货号`。
- 二级键：`平台 SKU + 属性`。
- SKC 和供方货号同时缺失时跳过。
- 重复导入相同一级键时，新导入批次替换旧分组。

### 2.4 行处理

- 变动类型包含“盘亏”时整行排除。
- 数量主字段为 0 时，尝试 `客单发货 + 平台客单`。
- 金额主字段为 0 时，尝试 `客单金额 + 平台金额`。
- 数量和金额都为 0 时跳过。
- 变动类型包含“扣款”“罚款”或“违约”时，只增加扣款，不增加销售数量和金额。
- 正常行累加数量、金额和来源行数。

### 2.5 标准平台台账报表模式

当工作簿首张明细表同时包含“变动类型、供方货号、SKC、平台SKU、属性集、数量、单价”列时，按标准平台台账模式处理：

- A 列“变动类型”默认只保留“平台客单发货”和“客单发货”，用户可以取消其中一种。
- C 列“供方货号”提取为可多选筛选项；一个销售人员可对应多个供方货号，不能把供方货号简单当作单一人员字段。
- D/E/G/H/I 列分别作为平台 SKC、平台 SKU、属性集、数量和单价。
- 标准模式销售金额按 `数量 × 单价` 计算，不依赖 J 列“金额”或后续活动/商家扩展列。
- B 列结算类型、F 列商家 SKU 以及 J 列之后的扩展列默认不进入利润核算；原始文件仍保留在导入批次外部来源信息中。
- 导入批次审计中保存实际选中的变动类型、供方货号和金额计算方式。

## 3. 成本粘贴与核对契约

- 至少识别一个 SKU 列和单件平均成本列。
- 同时为平台 SKU 与仓库 SKU 建立查找索引。
- 利润明细优先按平台 SKU 匹配，必要时才使用仓库 SKU 兜底。
- 同一键出现多条有效成本时，兼容行为是最后一条有效值覆盖前值。
- 无效或空成本不得清除先前有效成本。
- 空订单号不得清除先前有效订单号。
- 新系统必须额外报告重复、覆盖和兜底匹配，避免静默发生。

## 4. 利润契约

```text
采购成本 = 数量 × 单件平均成本
仓储成本 = 数量 × 仓储费率
利润 = 金额 - 采购成本 - 仓储成本 - 客退罚款
```

- 默认仓储费率为 `0.70 CNY/件`。
- 成本缺失时可以查看明细，但利润不能标记为正式结果。
- v8.0 的来源行数不是去重订单数；新系统必须分别命名和统计。
- 兼容 Excel 固定列为：SKC、SKU、属性、数量、金额、单号、单件成本、采购成本、仓储成本、客退罚款、利润。

## 5. 选品工作台契约

- `CaptureEnvelope v1` 保持版本化校验和大小边界。
- 采集记录先进入 `pending`，不能直接进入正式商品库。
- 重复检测顺序保持：采集请求 ID、来源平台+商品 ID、规范化来源 URL、来源平台+来源 SKU ID。
- 确认入库保存采集请求 ID 与正式商品 ID 的关联。
- 原子写入、备份、隔离损坏文件和恢复标记的可靠性语义必须迁移到云端事务、版本记录和本地离线队列。
- 扩展密钥不能暴露给内容脚本；ERP 和 1688 登录凭据不进入 Shopeers 云端数据库。

## 6. 允许的改进

以下改进不视为破坏兼容：

- 用数据库事务替代 localStorage/JSON 主存储。
- 用内部 API 自动传递成本批次，同时保留 TSV/CSV 降级通道。
- 给账本增加自然月隔离、状态机、审计日志和真实订单数。
- 对重复覆盖、无映射、人工兜底和后补 ERP 成本显示明确异常。
- 在不改变公式的前提下使用十进制库避免浮点误差。

任何改进都不得改变既有数据在相同输入下的核心选择、聚合和利润结果。
