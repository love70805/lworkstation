# ERP 微小单件成本与窗口化选品页修复

状态：用户已批准 ERP 单价四位及“先精确累计、最后截断”；利润与 ERP 实施中。选品窗口修复完成审查与前端回归。尚未发布。

## 根因与目标

正式 0.2.7 将低于 0.01 元的真实 ERP 加权单件成本截断为零，发布门禁阻止正式成本，但没有异常处置区域。用户确认原始单价真实，不能引导抬高价格。另有按仓库 SKU 分组后搜索非代表平台 SKU 隐藏处置区域的独立缺陷。

目标是让真实低价经过证据复算、发布、保存、利润核算和导出保持有效精度，并保留已定稿历史；商品库操作控件在普通桌面窗口可见可用。

## 已批准数据与计算合同

1. CNY 正式 ERP 单件成本按既有加权选样规则计算后使用 Decimal.ROUND_DOWN 保留四位；此精度贯穿预览、正式发布、成本策略、存储读回和 ERP 历史引用。不得在消费端再次截成两位。
2. 正式采购成本为数量乘四位单价，行金额保留精度；以 Decimal 累计原始行金额，账本/月度总额出口才 ROUND_DOWN 到两位。不得逐行或先分组截两位再求总额。
3. 利润从未截断的采购成本及现有销售原额、仓储、扣款口径计算；累计完成后截两位。利润率使用同一精确基础，展示截两位。展示金额相减可能存在一分钱尾差，不能为了凑显示数改变精确结果。
4. 筛选汇总和分组展示从原始精度计算；账本定稿总额始终使用全账本原始行，筛选或排序不改变定稿结果。ROUND_DOWN 对负值向零截断。
5. 单价显示四位；非零且绝对值不足 0.01 的金额明确标识微小金额（负值保留方向），实际零显示 0.00；导出保留真实行精度并说明汇总规则，不能将显示文本作为数字落盘。
6. finalized/locked 账本使用已保存 profitLines、profitSummary、formulaVersion 展示和导出，不按新成本或算法重算。只有用户显式重开后的账本采用新规则；新定稿重载应与定稿前一致。缺少历史快照时明确提示缺失，不编造重算结果。
7. 更新策略、公式和成本决策版本，保留原始证据与审计。优先沿用现有数值字段及版本字段；不新增 exact 重复字段。用户另行批准追加 0011 云端迁移与测试：仅将 profit_lines.purchase_cost 和 profit 从 numeric(18,6) 放宽为无固定 scale 的 numeric，保留旧数据数值及权限/事实保护；以支持现有小数销量乘四位单价的完整行精度。本轮不执行线上迁移。
8. 正式单价截四位后仍为零时禁止发布并说明精度边界，不诱导修改真实价格。ERP 优先、1688 仅参考、人工审批要求、采购记录选样和权重不变。

不扩大到 1688/人工参考算法、ERP 扩展、数据库清理或真实业务数据改写。迁移由利润与 ERP 作为该数值合同主责实现，独立提交并注明跨域原因；必须用 PGlite/Postgres 验证十位小数写入和旧值保持，不只检查 SQL 文本。本合同取代此前“两位成本补齐更正入口”的草案。
