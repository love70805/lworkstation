# 预存区分阶段建档契约（0.4.5）

用户于 2026-10-07 修正流程并选择完整标准：导入 → 预存区 → 逐步补齐 → 自动进入选品库。基线 a420fe7 / v0.4.4，分支 codex/v045-prestorage。此契约替代 0.4.4 中基础草稿直接展示在选品库的流程。

- 继续复用产品 draft/active 状态与 SKU 全局归属；draft 展示在预存区，正式及停用档案展示在选品库。上一版 ledger_import 草稿自然归入预存区，不运行历史批量迁移。
- 完整标准：有效名称、图片、店铺、SKC、至少一个 SKU，全部保留 SKU 有属性、非负有效售价与可用参考成本，至少一个有效供应商来源链接；未解决身份、资料来源、名称选择或旧状态冲突阻止自动进入。零售价是有效值，空值不是零。
- 预存资料可以逐次保存；保存和 ERP 资料/参考成本回传后重新检查。自动流转写入产品、SKU、供应商与审计，重复检查不重复发布；人工字段优先，已正式档案不自动退回，业务销售状态独立。
- 旧人工草稿仍可补齐；只有导入草稿及用户在新流程中保存过的预存资料参加自动流转，避免自动发布旧人工草稿。未建档历史来源仍可进入预存流程，已正式档案的参考历史可显式查看。
- 自动化使用当前工作区可访问资料，写入时重读并检查身份/完整性，事务保证原子性；失败显示并可重试，不导致 ERP 收件丢失。月度正式成本、人工月度更正和利润定稿口径不变。
- UI 保留旧 reference URL，名称改为预存区，提供缺项、补充资料和流转结果。分组明细继续提供参考成本/利润帮助逐步补齐。

验收：仅标识的导入不出现在选品库；部分资料保存留在预存区；最后缺项补全/可信 ERP 回传触发一次自动进入；来源冲突、全 SKU 缺项、人工清空、权限及工作区切换阻止错误流转；正式档案和金融历史保持；旧草稿、连续补齐、失败重试、浅深色窄屏与规模样本通过。完整测试、生产构建、桌面验证与隐藏候选、CI、稳定发布及公开资产回读按项目授权连续完成；不安装或操作真实业务库。

实施验证：1324 项前端测试、完整 ERP 门禁、desktop verify、实际隔离 CSV 导入及后台回传路径通过；流转每组最多 20 份，整组异常回滚并可重试。安装包与公开资产结果另见发布记录。
