# 0.3.7 ERP 受控本机恢复契约

基线 `454b74f`，ERP Assistant 8.0.28。批准范围见本版升级计划。

- 检查点只由扩展后台 `chrome.storage.local` 管理，按工作区、台账月份、requestId、完整 SKC/SKU 目标集合、查询条件、扩展版本及请求登记版本绑定；后台每次恢复重新读取受控收件服务中的登记请求。页面不能指定收件端点或工作区。
- 只保存继续操作所需的请求、经过白名单筛选的查询条件、完成目标进度和稳定投递身份，不保存 Cookie、Token、登录响应或凭据。最多八项、合计 1 MiB、24 小时；启动、定时和访问时清理。超限不能冒充已保存。
- 跨刷新/重开/浏览器重启提供“继续未完成采集”。当前生产字段证据没有可确认当前账号及采购历史版本的接口，恢复时显示“重新核验账号与采购历史”，所有目标重新查询；不能将无法核验的历史证据复用为正式完整成本。同页面新一次继续同样重新核验，不能假定账号未切换；登录失效、查询/请求/工作区/月份变化立即隔离。部分目标重新读取每一页，不再仅凭首页一致复用后页。
- 成本先展示和进入既有持久 ACK 送达队列，可选资料随后补充。读取完成、待继续、送达、采用分别描述；扩展无法确认采用时明确“待工作台采用”，不把传输 ACK 当作采用成功。
- 不改正式利润、更正优先、定稿及同 SKC 映射口径；无数据库迁移。验证使用独立合成和现有脱敏生产字段回放；当前 CUA 仅列出无标签的 Edge，现场账号新采集尚未通过。

## 验证结果与限制

- `erp-collection-recovery.test.mjs`：生产后台 VM 重启、仅保留扩展 storage 的刷新/重开/重启生命周期；跨月份/目标/SKU/登记版本/台账/工作区失效、24小时过期与扩展版本变化、白名单及未知查询条件拒绝、八项容量上限、稳定投递身份、丢失ACK优先重投原始已持久载荷、晚到ACK不结束新任务、不完整ACK保留继续并分配下次投递身份。
- 5000个合成目标检查点 `520653` UTF-8字节，最近一次保存26ms；上限按UTF-8真实字节计算。没有原始采购明细或凭据进入检查点。
- 602订单/14页、大范围/重复页/总数变化/登录失效/取消和预算保护；同一页面三次尝试均重读已完成列表，模拟账户证据变化后采用本次新价格。五分钟仍为单次成本阶段预算；当账户/历史版本无法证实时不会为跨预算提速而拼接未经核验的旧证据。持续超过预算的任务仍需重查，不能宣称可无限渐进完成。
- 已有生产字段脱敏采购回放、扩展生成包/ZIP一致性及安全bridge测试通过；成本先于可选资料、目录故障不倒退成本仍通过。
- Headless Edge 154.0.4258.48：1440/1000/390宽度、浅/深色浏览器偏好六布局，继续按钮键盘Enter、取消实际待响应请求74ms内反馈，无横向溢出；沿用现有浅色扩展面板，未增加深色重设计。截图和汇总仅在忽略目录 `archive/release-0.3.7/erp-recovery/`。
- 当前工具枚举没有可访问已登录ERP标签。以上为生产代码隔离回放和合成浏览器交互，不是现场账号新采集；未访问真实收件服务、未写真实业务库、未安装扩展。账号/分页历史版本现场验证仍是明确缺口。
