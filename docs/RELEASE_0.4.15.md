# 0.4.15 启动后空闲内存增长修复

用户安装 0.4.14 后无操作，工作台 renderer 私有内存达到约 2.5–3.1 GiB，CPU 持续忙。三个包含价格异常的 partial 成本批次在后台每五秒被重新处理；即使结果未变，仍更新批次并使财务派生缓存失效，反复校验证据与重建商品资料。

现在只有采用结果变化才同步批次元数据；无变化的成功检查复用内存结果，来源变化和失败仍重试。后台进度只读取小型采用状态投影，主页与预存检查共用既有 compact 参考计算。保持价格异常约束、人工更正优先、定稿与锁定保护；不增加迁移，不重置数据。

隔离回归先复现三个无变化检查仍三次写入，修复后不写入、不变更来源版本，也不再次读取采购证据；人工更正、锁定/解锁、旧元数据补齐、撤销和工作区切换仍刷新。174 文件 / 1367 前端测试通过。

同一份只读一致数据库副本含 8657 台账行、110 商品、367 正式 ERP 成本和 7 异常。原版与修复版相同入口、Electron 44.2、隐藏窗口、冷派生缓存，不强制 GC。Electron 进程私有内存在约 40 秒时由 1548.4 MiB 降至 425.1 MiB（约 72.5%），最终 181 秒空闲观察在 414.9–428.3 MiB，结束 422.6 MiB。此组不含独立 Node 收件服务，候选需另记录完整进程树；不是任意登录页或任意规模资料的绝对占用承诺。真实应用未被重启/关闭或改写，未安装。

基线 main `8b1d8ee` / 0.4.14，实现 `1a71336`，契约见 [启动内存](integration/STARTUP_MEMORY_GROWTH.md)。候选安装包、完整门禁、候选同数据副本和用户路径验收进行中；尚未公开。证据只保存在本机 `archive/startup-memory-growth/`，业务副本不提交或上传。
