# 0.3.9 采集、映射与范围筛选修正

2026-10-06 用户反馈本机 0.3.8 采集在 `ERP_CHECKPOINT_QUERY_UNSUPPORTED` 停止、导入映射显示大量未映射，并确认利润和选品两个面板都需要完整导入后缩小范围搜索。本批沿用未公开的 0.3.8 分支和 PR #137，保留旧候选；修复版本为 0.3.9，使已安装 0.3.8 能识别更新，包含尚未公开的图表和图标优化。通过验证后按现有授权统一公开，不覆盖安装或修改真实数据库。

## 契约与影响

- ERP 恢复快照保留当前采购表单的完整已验证查询字段，不丢弃有意义的范围条件。2026-10-06 只读查看已打开采购框架的 DOM 和 `purchasingManagement.js`：官方 `searchArr` 包含异常状态、商品名称、在途时长、采购人、1688 账号名称、建议付款等字段；提交时另加 `mineableType`、`buildType`、`purchaseStatus`、`adjacentToTheSameSupplier`，排序使用 `sort`。旧白名单缺少这些正常字段，连默认空条件也会触发截图错误。新扩展追加这些经过源代码核对的字段；恢复时保留空条件，避免保存下一检查点时被误判为范围变化。成本沿选定目标展开完整采购历史，新增临时展示条件与已有时间/状态条件同样展开，保留店铺与目标。未知字段、凭据排除、大小/有效期限制、原请求绑定和完整证据规则延续。扩展升级到 8.0.29，安装包与下载 ZIP 同源。
- 五份八月台账均有数量、单价、SKC、平台 SKU、添加时间等核心列。标准台账销售原额继续由数量乘单价计算，金额与成本备用字段不擅自用于正式核算。映射界面区分自动匹配、计算所得、默认店铺、源表无可选列和真正必需缺项。`业务单号` 可作为订单号，`添加时间` 不冒充订单日期，不把 `单据号` 猜成订单号。无数据库迁移。
- 台账仍完整导入。利润、选品列表先按店铺/货号等范围筛选，再搜索 SKC/SKU；只在当前范围建立和使用搜索文本，复用不变行的文本。总账和定稿数据不因视图筛选改写。
- ERP 登记与回传验收使用当前筛选后的目标 SKC 和 SKU 对。范围改变使旧请求失效，不能把先前范围的结果重绑定新范围。完整性、人工更正优先和定稿保护继续生效。
- 桌面构建依赖定向更新缓存库并移除未使用的旧下载器可选代理链，保留现有 Electron 本地打包、安装下载及更新链；依赖审计门槛不变。

## 验收信号

1. 使用官方完整查询字段的生产 content→background 回放能保存快照、读取第一页并回传；恢复保留字段，改变真实条件被拒绝，未知字段继续明确报错，凭据不落快照。
2. 五文件只读导入仍保留原完整来源、数量及收入，核心字段不误报缺失；备用字段的无映射有明确原因，不增加确认步骤。
3. 利润和选品面板在全部及店铺/货号范围内搜索正确，清空筛选能返回全量；范围外数据不进入本次 ERP 登记，切换范围后旧请求不能继续自动采用。
4. 运行适用前端、桌面门禁及新包实际用户路径；检查中文、浅深主题与窄屏。发布依赖审计通过后再集成、打包、上传并匿名回读公开资产。真实账号只读核对不算真实业务回传通过。
